日期：2026-10-21。基线 main / `3ea13e3`，修改前工作区干净，原 HEAD 为回退点。代码图服务没有索引本项目，本轮按项目约束回退到源码和文件检索。版本保持 0.3.0 本地候选，schema 8；没有公开发布、签名、tag 或 push。

## 本轮改动

1. 书架每页最多 48 本，任务每页最多 20 项；提供首页、前后页和末页，任务增加状态筛选。搜索覆盖全部作品，搜索/归档筛选变化后回到第一页，结果缩小时修正页码。
2. 标签使用按作品 ID 建立的 Map，避免为每本作品反复扫描全部偏好记录。主书库快照和偏好并发请求。
3. 主书库快照改为完成上次刷新后再计时：空闲约 5 秒，运行任务时约 800 ms；窗口不可见或原生最小化时跳过自动快照读取，恢复窗口时重新刷新。手动操作完成后重新调度，避免新任务等待空闲周期。
4. 重复导出在生成临时文件前给出明确的“导出文件已存在”提示；并保留最终 `persist_noclobber` 的并发不覆盖边界。既有文件和正文不变，不添加虚假的导出记录。GUI 与 CLI 共用核心。
5. 明确归档空状态，修正备份工具页标题；侧栏导航样式限定到侧栏，避免影响新分页控件。

刷新统计只针对主书库快照。批次面板在任务页仍有独立的 1 秒状态轮询，后台下载并不会因窗口最小化而停止。本轮未更改来源权限、数据库 schema 或凭据处理。

### 最小化与暂停恢复回归

实测发现本机 WebView2 在主窗口最小化后仍报告 `document.hidden=false`。旧网页可见性方案的检查失败：最小化期间仍发生一次快照读取。补上原生 `isMinimized()` 和窗口恢复/尺寸事件后：

- 真正最小化的主窗口，5.5 秒内自动快照读取 **0 次**。
- 恢复主窗口后自动刷新。
- 五千章原创导入运行时，2.5 秒观察到 3 次主快照刷新。
- 保存到 1088 章时暂停，等待后计数保持不变；继续后完成 5000 章，末章可读。

测试使用属于本轮进程、准确标题为 OpenNovel Downloader 的主 HWND；不使用最小化后可能选中空标题辅助窗口的 `Process.MainWindowHandle` 作为恢复目标。没有操作用户其他窗口。
