# 健壮性、性能、隐私与平台风险复审

日期：2026-11-04；基线：`1317529`，修改前工作区干净。证据根目录：`.artifacts/release-review-20261104/`。本轮不使用真实账号、个人书库或 Computer Use，不向小说平台施加压力测试。

## 当前结论

已有持久化队列、正文与完成状态同事务、取消与进程崩溃恢复、导出同名保护、独立用户、受控 IPC、固定来源校验及隔离引擎；这些是可维护桌面软件的基础。本轮发现并修复了请求范围、冷却和默认速度方面的缺口。

不能据此给出“全平台稳定上线”“不会泄露任何数据”或“账号绝不受风控限制”的结论。工程检查、真实平台支持、用户账号权益、平台授权、干净系统和正式分发信任是不同门槛。可交付范围必须限定在已验证能力，不能把实验通道、网页目录成功或登录窗口打开当作完整正文能力。

## 发现与处理

| 发现 | 影响 | 本轮处理 |
| --- | --- | --- |
| 增强任务把全任务 ID 发给预取组件，忽略本次失败章节选择，也未先排除其他任务已保存的正文 | 可能提前请求不需要的邻章，浪费时间与平台请求预算；核心最终写入范围仍有约束 | 增加单次 SQL 缺失计划，排除已保存、受限及本次未选章节；无效重试选择失败关闭；直接取作品摘要，避免解析整份目录和章节状态 |
| Rust 增强适配器每章线性扫描 ID 列表 | 万章队列重复身份检查最坏呈平方级累计工作 | 保留有序 ID 列表供传输，额外使用 HashSet 作均摊常数时间成员检查 |
| 三个增强预取会话没有共享请求启动间隔 | 网络快时会连续突发；重试也占用额外请求预算 | 同一个工作进程的三个会话共用至少 500 ms 启动间隔，包括有限重试；保留最多三个在途请求、连接复用和有界缓存 |
| 增强限流只展示等待文字，新适配器可立即重启 | 用户连续点击继续会再次访问来源 | 宿主按用户原子保存冷却截止时间，重新打开程序仍检查；较短的后续等待不能缩短已有冷却；只保存时间，不保存书籍或账号标识 |
| 不同作品/不同账号可以在同一平台叠加自动任务 | 单任务节奏不等于程序总访问节奏 | 同一程序中本地增强只允许一个自动任务；账户通道同平台只允许一个自动任务 |
| 后台默认 3 秒，界面及 API 却默认为 0.5 秒 | 普通用户无意进入激进翻页档 | 起点首次保存、继续面板和 API 默认统一 3 秒；快速档保留主动选择，明确账号风险 |
| 主窗口未拒绝全局 WebView2 数据目录覆盖 | 环境覆盖可能使不同本地用户共享 WebView 偏好/数据 | 在读取书库和创建主窗口前拒绝 `WEBVIEW2_USER_DATA_FOLDER`；官网账号窗口原有拒绝逻辑保留 |
| HTTP `Retry-After: 0` 可形成无冷却状态 | 后续继续可能立即重发 | 公共 HTTP 冷却最短 1 秒，保留 HTTP 日期解析和最长 24 小时界限 |
| 组件准备失败或增强任务名额占用后，新任务仍可能显示排队 | 界面像在工作，实际没有执行者 | 记录可恢复的准备失败状态，保留原任务与待保存章节；迟到错误不能覆盖用户暂停/取消 |

不取消 SQLite FULL 同步、不移除完整性校验、不自动处理验证码、不增加付费权限、不引入代理轮换或指纹伪装。

## 性能结果与适用范围

原创样本：10000 章，9000 章已有正文，选定 5 个失败章。release 模式，5 组，每组各生成 20 次计划。旧路径为 `book_details + job_details`，新路径为 `book_summary + pending_download_ids`。两条路径使用同一数据库，均没有网络请求。

| 样本 | 旧路径 20 次耗时 ms | 新路径 20 次耗时 ms |
| --- | ---: | ---: |
| 1 | 573.258 | 70.997 |
| 2 | 561.474 | 68.878 |
| 3 | 552.338 | 68.890 |
| 4 | 542.722 | 69.911 |
| 5 | 541.643 | 68.104 |

中位耗时约从 552.338 ms 降到 68.890 ms，约 8.02 倍；每次约 27.62 ms → 3.44 ms。组件收到的允许预取 ID 从整份 10000 项缩小为选定 5 项；**这不表示旧版真的发出 10000 次请求**，旧版只有滑动窗口预取，本轮减少的是允许范围和多余邻章请求。证据：`planning-benchmark.json`；复现命令：`cargo test -p opennovel-core --release --test local_engine_queue prefetch_planning_benchmark -- --ignored --nocapture`。

这不是全书端到端加速 8 倍。全书耗时通常受官网延迟、阅读加载、每章稳定性确认、请求节奏和平台冷却约束。新建任务未命中缓存时，共用 500 ms 节奏的增强通道，1000 个请求的启动跨度至少约 499.5 秒；账户默认 3 秒时 1000 次翻页约需 50 分钟，实际还可能更久。用户可主动选择更快账户节奏，但不能承诺任意长书三分钟或不触发验证。

## 隐私与危险操作检查

| 边界 | 代码现状与限制 |
| --- | --- |
| 密码与 Cookie | 用户在官网 WebView 自行登录；本地 accounts 表只存随机 ID、平台和别名。正文提取脚本读取限定 DOM，不主动读取 Cookie、本地存储或系统浏览器账号。官网本身仍可处理用户输入及请求 |
| 网络外发 | 主界面 CSP 限制外站连接；公共来源固定 HTTPS 域名、禁止 URL 凭据及越界重定向；增强转发固定主机/路径/参数/头，拒绝 Cookie/Authorization、私网 DNS 和失效 TLS。未发现应用自身的遥测、云端书库同步或向解析服务上传账号的实现。官网自身子资源不受顶层导航白名单完全约束 |
| 本地数据 | 当前 Windows 用户目录与软件用户 ID 分区；数据库、导出和备份不是加密文件。同系统用户、管理员、恶意本地软件仍可读文件；共享盘或云同步目录可能复制用户主动导出的内容 |
| 不可信文本 | 主界面文本呈现；正文导入/平台响应有长度、身份及结构约束；TXT/DOCX/EPUB 使用受控命名与 XML/HTML 转义。没有以正文内容构造 shell 命令 |
| 原生危险边界 | Windows 文件对话框与组件隔离使用 FFI/ctypes，应继续重点维护。引擎校验固定字节和源码清单后在无网络 AppContainer、kill-on-close Job 内启动；宿主传输只接受固定协议。无法启动沙箱时拒绝降级 |
| 日志与反馈 | 默认诊断仅版本、系统、数量、任务状态及数据库完整性；不含书名、正文、账号别名或凭据。源码与锁文件扫描不上传书库；npm 审计发送依赖包名/版本到官方审计服务。用户不要把整个数据目录或浏览器崩溃转储公开上传 |
| 分发 | 白名单构建、组件哈希核验及 ZIP 条目校验保持；用户数据不作为新用户模板。正式代码签名尚未完成，不能把依赖自身签名当作应用已签名 |

以上为明确范围内的源码审查、测试和运行验证，不是专业第三方渗透测试或“零泄露”认证。无法证明本机恶意软件、用户指定共享位置或平台页面不会外传信息。异常退出的临时浏览器目录亦不能承诺安全擦除。

## 平台账号风险

技术上停止验证码、限流、失败重试和跨域访问，只能降低请求堆叠与误操作，不能取得平台授权，也不能推断其内部风控阈值。登录状态下的持续自动翻页仍可被识别为自动化；免费或已购内容不等于允许外部工具批量保存。

本次查阅的[起点读书用户服务协议](https://acts.qidian.com/pact/userpact20220316.html)页面标注 2022-03-16 版本，第 4.1 条约定认可的使用方式及第三方工具边界，第 4.2 条约定违反后的服务终止。这里仅说明可核实的协议风险，不替平台作出账号处理承诺，也不作法律结论。不同平台须逐一复核最新协议或取得相应授权。

尚无跨程序、跨软件用户或跨 Windows 用户的统一请求预算；多开仍可能叠加流量。本地增强冷却为当前本地用户的宿主约束，公共 HTTP 冷却仅存于对应客户端生命周期；不应宣传成全局永久风控保护。
