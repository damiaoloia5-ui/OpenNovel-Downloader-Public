# 起点验证后恢复修复

日期：2026-10-30。修改前 Git 干净，基线 `82ee2b3`；图工具返回未索引后读取源码。本轮不使用 Computer Use、浏览器/窗口自动化或真实账号凭据。

## 证据与定位

用户反馈保存中出现滑块，点击继续后立即停止/报错。对原启动入口指向的书库执行 SQLite `mode=ro` 查询，仅检查任务计数和错误类型，不读取正文、不写库。最近任务为 partial，1448 章中 127 章已存、1 章 failed、1320 章 queued；错误匹配“读取期间页面导航发生变化”。没有发现已保存进度丢失。当前运行窗口和实际验证页面未检查，不将该库的结果外推到其他启动入口。

核心已实现明确恢复后的 failed/blocked 重排和缓存复用，问题不是缺少全部断点机制。源码确认两处恢复缺口：没有只显示原验证页的入口，既有“打开”操作会导航；账户适配器每次 fetch 均导航到目标，即使本人刚完成验证、当前页已是该章节也重载。重复加载可能重新触发检查，这是源码推断，尚无真实官网前后对照。

## 修复

- `focus_account` 验证本地账户记录后，通过原窗口 show/unminimize/set_focus 恢复可见与焦点，不调用 navigate、reload 或重建会话。接口依据 [Tauri 官方窗口文档](https://v2.tauri.app/reference/javascript/api/namespacewebviewwindow/)，沿用既有本地主窗口 IPC 守卫。
- `resume_account_download` 在启动 worker 或修改任务队列前，先取得短期读取租约，检查官网白名单、登录域名，并读取不含正文/凭据的可见页面状态。回调最多等待 8 秒，返回上限 1024 字节，只接受唯一 status 字段及 ready 值；loading、verification、unknown、无效或超长结果不启动任务。错误路径由 RAII 释放读取标记。验证码仍在时恢复原窗口并提示本人处理。
- 状态检查返回后核对完整地址、导航版本和会话 generation；启动前再核对版本票据。没有取消原有导航、账户和正文守卫，也没有强行清空仍在执行的任务登记。
- 当前清洁地址等于目标章节时不再 navigate；仍执行页面 complete、两次相隔 400ms 的一致读取、身份/标题/字数校验及逐章事务。其他章节沿用串行导航和节奏。
- 识别已知可见滑块容器、含验证文本的 dialog 和验证码/安全验证 iframe。仅检测，不点击、拖动、解密或操纵验证状态。检查未发现验证不等于证明登录、权限或验证通过；后续正文校验继续执行。未知挑战仍可能只表现为导航/超时错误。
- 前端提供原窗口入口、明确本人完成后继续、失败后的再次尝试；原任务与范围保留，检查失败不创建新任务。导航/验证中断时将低于 3 秒的界面设置建议为 3 秒，用户仍可调整；不承诺不会再次验证。
