## 变更与设计

- `capture_page.js` 在一次同步提取内使用 WeakMap 缓存每个节点及祖先的样式可见性。原有逐元素祖先遍历会为共享祖先反复调用 getComputedStyle；缓存后样式查询随不同节点数增长。元素自身的布局矩形仍逐元素检查。缓存随提取结束丢弃，下一次提取重新检查全部限制，不跨章节、页面或轮询复用。
- 自动队列仍获取两次相隔 400ms、内容完全相同的正常页面结果。首次完整解析通过后，第二次相同字节结果复用已校验正文；更改、加载、验证、订阅或超长结果先清空旧结果，再重新判断。每个稳定检查器绑定一个预期地址及章节引用；调用方每次仍核对地址、导航版本、账户会话和取消状态。
- 已解析的会话章节直接走核心结构化校验，移除 JSON 序列化后再解析的往返。正文预算、归一化、字数检查、章节身份与标题检查保持原规则。
- UI 默认新增 500ms 极速档，接受值仅 500/1000/3000/6000ms。旧 IPC 省略参数仍为 3000ms；节奏只在启动/继续时应用。保持单个官网任务串行、页面 complete 检查、单章 30 秒和异常停止。

## 受控性能证据

### 提取脚本

`scripts/qidian-capture.test.mjs` 使用 node:vm 执行实际脚本，测试对象是原创 DOM 结构替身，没有启动浏览器。由 1000 个原创段落、内嵌 span、共享的八层祖先和隐藏后代构成。基线脚本由修改前 HEAD 导出到忽略目录。显式执行：

```powershell
$env:OPENNOVEL_CAPTURE_BASELINE="$PWD/.artifacts/qidian-speed-20261030/baseline-capture.js"
node --test scripts/qidian-capture.test.mjs
```

新旧返回结果逐字段相同；getComputedStyle 调用由 **37056 次降至 2014 次，减少 94.56%**。这是确定性的调用次数，不是 WebView 渲染耗时。受控对象不能证明真实 CSS、页面布局或原生行为。

### 稳定确认解析

```powershell
cargo test -p opennovel-desktop --locked stable_decode_benchmark -- --ignored --nocapture
```

500 个原创长章节、每章两次读取，当前解码器重复解析 **874.607ms**；首次解析加相同结果复用 **441.650ms**，本次单轮减少约 49.5%。该测试隔离重复解析开销，使用 debug 测试程序，不是全项目修改前后端到端对照，不包含页面加载、IPC、数据库或导出，也不将单轮耗时作为稳定性能保证。

500ms 档在忽略页面加载等开销时，千章仅导航节奏下限约 8.3 分钟；原 1000ms 档约 16.7 分钟。页面完成及 400ms 稳定确认可能决定实际耗时，这只是推算，不承诺整书完成时间。
