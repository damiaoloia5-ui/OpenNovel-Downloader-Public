# v0.3.23 原生窗口与独立用户验收

2026-11-05，源码基线 `18b98ac`，修改前工作区干净。本轮补验现有交付程序，不修改生产代码、依赖或安装包，不递增版本。

## 测试对象与方法

使用 `.artifacts/delivery-0323/OpenNovel-0.3.23-Windows/OpenNovel.exe` 的逐字节副本，SHA256 为 `d77bd4009f02ff465abfbce3b17728f705cb45d19eeb771162785ae926d3c37d`。测试完成后再次确认副本与交付程序摘要相同。

通过仅限测试进程的 WebView2 本机随机调试端口，用 Playwright 操作真实 Tauri 原生窗口，而非浏览器预览。界面动作包括点击、输入、选择格式、导入和切换用户；只读 IPC 快照用于补充核对书库与当前用户状态。测试使用原创 JSON，不使用真实平台账户和小说正文。未使用 Computer Use。

GUI 用户索引由 Windows KnownFolder 路径确定，单独改变 APPDATA 环境变量不能隔离该索引。因此本轮先备份原索引和原有数据摘要，在索引中暂时登记两个独立测试用户，未打开原有用户书库执行测试。恢复时持有索引锁并核对原用户条目未变化，再原子恢复原索引。

## 仍需推进的边界

- 本轮完成的是这台 Windows 机器上的原生导入、阅读、导出和应用内用户隔离；不是独立干净 Windows 的安装、跨版本更新或不同操作系统用户验收。
- 真实已购账户连续全书、七猫 App 通道、平台图片正文仍未由本轮验证；Windows Authenticode 仍未办理。不能把本地原创场景通过等同于所有来源都能完整下载。
- 目录识别目前没有贯穿前后端的主动取消：前端丢弃过时结果不等于中止后台请求，已有下载任务取消也不能覆盖识别阶段。应单独实现取消令牌传播和中断测试，不能在本轮记为已完成。
- 本轮只有验收文档和任务记录变更，执行证据交叉核对与 `git diff --check`；未重复运行全量 lint/typecheck/test/build。生产构建的既有回归见同日 [目录效率与正文保真复核](2026-11-05-pagination-efficiency.md)。

本轮不 push、不创建标签、不公开 Release。
