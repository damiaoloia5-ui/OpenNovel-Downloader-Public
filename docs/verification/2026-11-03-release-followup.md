# 发布签名流程与安装自检入口补验

日期：2026-11-03；基线 `cc686e95c043304a463cb6458c6c400ff5f85a2d`，版本仍为 0.3.19。本轮不改变下载适配器、数据库 schema 或阅读权益范围；候选安装包仍未正式签名。

## 已修复的签名流程缺口

Tauri 打包签名后会恢复构建目录内未签名的独立桌面 EXE。原发布流程只补签 CLI，随后直接验证独立桌面 EXE，会在取得正式证书后仍失败。现在对两份独立可执行文件签名后，再验证签名、时间戳和卸载器审计，最后计算交付摘要。签名候选交付也包含安装自检入口，并纳入摘要清单。

隔离测试运行实际编排脚本的副本，假构建器模拟恢复未签名 EXE；修复前成功分支确实失败，修复后通过。另验证桌面签名失败、安装器未签名、卸载器审计缺失时不会生成交付目录。测试使用原创假工具及明确标注的假签名，不访问证书或私钥；生产流程没有增加跳过签名验证的开关。正式 CA 签名仍未实测。

## 普通用户自检

基础与一体化安装器新增 `运行安装自检.cmd`。便携目录同样附带，双击可运行已有原生原创样本检查，不要求安装开发工具。每次产生独立报告，显示基础检查与可选组件状态；不打开原书库，不请求小说平台。使用方法见[第一次使用](../QUICK_START.md)。

四项 Windows 进程测试覆盖安装版文件名、便携版文件名、中文/空格/特殊字符路径、默认输出目录、缺失程序、GUI 进程错误码。测试清空 PATH，使用原创 Rust GUI 子系统夹具，验证实际批处理执行而非仅检查脚本文本。

托管安装验证脚本增加已安装自检入口摘要核对，在安装和重装后清空 PATH 执行入口，并在卸载后检查入口移除。首次本地交付时尚未执行新的远端 CI；之后实际复验的结果见本文末尾，不沿用上一提交的结论。本机限制仍保留，没有在开发者日常系统执行静默安装/卸载。

## 首次远端验收发现的测试隔离问题

用户授权后，`64ef389553734d995f0cf4e40f4332a36f2ab4c2` 已推送。[运行 41629657210](https://github.com/damiaoloia5-ui/OpenNovel-Downloader/actions/runs/41629657210) 的 fmt、Clippy、Rust、前端检查通过，Python 在已有 `test_stale_sequence_closes_without_requesting_content` 的就绪消息等待处失败；安装和审计尚未执行，不能称本轮远端通过。原始日志在 `remote-first/`。

定位发现协议测试结束时只回收主工作线程，后台输入线程仍可能存活；全局 stdin/emit 在下一测试被替换，迟到的输入线程可能消费下一测试的配置。使用原创队列夹具延迟输入线程 0.2 秒，旧测试清理立即返回且线程仍活着；修复后等待约 0.203 秒，清理返回时线程已退出。测试同时固定使用原创 Session，避免本机是否存在可选引擎影响该测试。

只修改测试夹具，未修改实际协议、超时、限流或下载实现。原有 3 秒消息断言仍保留，未通过增大超时掩盖问题。受控前后对比及 200 次连续协议测试通过，证据为 `protocol-isolation/report.json`。首次失败报告保留，不被后续结果覆盖。
