# 发布签名流程与安装自检入口补验

日期：2026-11-03；基线 `cc686e95c043304a463cb6458c6c400ff5f85a2d`，版本仍为 0.3.19。本轮不改变下载适配器、数据库 schema 或阅读权益范围；候选安装包仍未正式签名。

## 已修复的签名流程缺口

Tauri 打包签名后会恢复构建目录内未签名的独立桌面 EXE。原发布流程只补签 CLI，随后直接验证独立桌面 EXE，会在取得正式证书后仍失败。现在对两份独立可执行文件签名后，再验证签名、时间戳和卸载器审计，最后计算交付摘要。签名候选交付也包含安装自检入口，并纳入摘要清单。

隔离测试运行实际编排脚本的副本，假构建器模拟恢复未签名 EXE；修复前成功分支确实失败，修复后通过。另验证桌面签名失败、安装器未签名、卸载器审计缺失时不会生成交付目录。测试使用原创假工具及明确标注的假签名，不访问证书或私钥；生产流程没有增加跳过签名验证的开关。正式 CA 签名仍未实测。

## 普通用户自检

基础与一体化安装器新增 `运行安装自检.cmd`。便携目录同样附带，双击可运行已有原生原创样本检查，不要求安装开发工具。每次产生独立报告，显示基础检查与可选组件状态；不打开原书库，不请求小说平台。使用方法见[第一次使用](../QUICK_START.md)。

四项 Windows 进程测试覆盖安装版文件名、便携版文件名、中文/空格/特殊字符路径、默认输出目录、缺失程序、GUI 进程错误码。测试清空 PATH，使用原创 Rust GUI 子系统夹具，验证实际批处理执行而非仅检查脚本文本。

托管安装验证脚本增加已安装自检入口摘要核对，在安装和重装后清空 PATH 执行入口，并在卸载后检查入口移除。**本轮改动尚未执行新的远端 CI，不能沿用上一提交的安装验收结论。**本机限制仍保留，没有在开发者日常系统执行静默安装/卸载。

一体化候选的实际 EXE 同样连续两次通过入口检查，报告保持独立；可选组件状态为 `installed=true, ready=true, enabled=false`，未启用引擎或请求正文。此状态检查不替代引擎全书或新系统首次准备验收。对应证据为 `candidate/launcher-check.json` 和其 `installation-checks` 下两份原生报告；最终 Python 全套仍为 95 项通过。

## 交付与保留边界

新一体化候选的验证副本为 `.artifacts/release-followup-20261103/candidate/`，基础测试副本在 `basic-launcher-check/`。纯交付目录 `delivery/` 只复制已核对的程序、完整组件、许可和文档，不复制验收样本数据库或日志，附 SHA-256 清单。旧 `.artifacts/security-delivery-20261103` 中的主程序、CLI 和安装器，以及原用户书库、桌面快捷方式 SHA-256 全部未变，证据为 `preserved-delivery.json`。

没有修改依赖，本轮不扩张已有安全审计范围；上一轮的依赖公告快照与引擎材料边界见[CI 与安全补验](2026-11-03-ci-followup.md)。仍待真实 CA 签名、普通干净 Windows/缺失 WebView2 分支、实际窗口与已购账号验收。不创建 tag，不发布 Release，不把这些自检称为全平台完整下载证明。
