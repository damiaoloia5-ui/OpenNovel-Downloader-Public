# 共用网页下载稳定性

2026-10-31，干净基线 b8dd6e5。用户澄清具体作品只是测试，主要目标是完善软件自身。本轮聚焦现有所有公开网页来源共用的获取、恢复与 TXT 链路，不以本地 TXT 补齐替代获取能力。遵守工程纪律、完成前验证及项目约束，知识图未索引后回退源码。未使用 Computer Use 或浏览器自动化，未请求商业官网或读写用户书库。

## 已复现的根因

1. WebClient 将 HTTP 401/403 作为 Restricted；核心将此类错误按单章受限跳过，可能继续请求同书后续全部章节。批次也仅因 network 错误暂停，无法区分全站挑战与单章限制。
2. 临时 502 等错误第一次即停止整本任务，要求用户重启任务。
3. 请求调度在等待间隔或 Retry-After 时持有全局 Mutex；冷却期间再次启动可能长时间处于运行态，没有立即反馈。

先增加两个原创 HTTP 回归，旧实现分别因 403 被当成单章受限、一次 502 后失败而测试失败，修复后再通过。

## 行为

- 共用 WebClient 对连接/传输错误及 HTTP 408/502/503/504 最多共 3 次尝试，重试前延迟 0.5/1 秒，并再次经过原有来源节奏调度。首个调度等待之后，整个请求与重试序列共享 20 秒预算，避免三次累计到 60 秒。永久错误、格式/大小/权限校验失败不自动重试。
- 429，以及带 Retry-After 的 503，不自动重试，立即停止当前运行；支持秒数和 HTTP 日期，默认 60 秒、最多一天，保留原有上限。此进程内的同来源客户端冷却尚未结束时，重复请求立即反馈剩余秒数且不发 HTTP。冷却状态未写入数据库，重启进程后不保留；没有宣称跨进程协调。
- 401/403 或 bdturing-verify 响应头产生独立 AccessChallenge，任务项记录为 failed / access_challenge，保留其原始原因并停止后续章；不把它表示为该章付费。批次在目录或正文阶段遇到挑战均暂停，后续书不请求。用户显式继续时，重用原任务、重试未成功章，已有正文不重新请求。
- 目录付费、锁定、已知试读等 Restricted 仍按原有来源规则跳过，不变更目录开放标记、字体、身份、字数或正文校验。
- 调度锁在等待前释放；节奏等待、重试等待与在途读取仍可取消。公开来源工作台不再建议登录无关的起点窗口，也不声称外部浏览器登录能授权 HTTP 客户端。
- GUI 和 CLI 共用核心；不迁移 schema，不新增外部正文服务、账户传递或来源回退。
