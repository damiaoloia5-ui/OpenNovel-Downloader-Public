# 作品工作台与状态引导验证

日期：2026-10-26。修改前为干净 `main`，基线 `3028536`。本轮整合界面，不修改 Rust 核心、IPC 命令、数据库 schema 8、来源权限或凭据策略；没有新增依赖。

## 本轮交付

- 新增作品工作台：概览、保存正文、阅读、导出四个页签。书架和全局任务可打开对应作品，新下载/导入任务根据核心返回的 book_id 进入工作台。
- 起点目录确认后进入本书保存页，保留选定账户；同一本书切换页签继续保留账户和当前阅读章节。更换作品/关闭应用后不承诺恢复阅读位置。
- 独立流程模型依据书库实际章数和任务状态提示下一步，区分选章完成与全书收齐。运行/暂停/失败/受限保留真实计数与原因，未开放来源不获得下载按钮。
- 失败/受限优先继续原任务，另建任务移到高级选章选项。批次统一控制、手动逐章、标签归档、目录历史和任务选章导出入口保留。
- 导出记住 TXT/EPUB 格式，切换作品或格式时清理旧成功提示；存储受限退回默认并允许本次使用。不改变导出目录，不覆盖旧文件。
- 组件加载代次和导航代次阻止迟到结果串入其他作品或把用户拉回已离开的页面；修订后重新读取当前正文，后台明细刷新保留分页。

设计见 [ADR 0011](../adr/0011-book-workbench-and-state-guidance.md)，操作见 [快速开始](../QUICK_START.md)。

## 受控真实浏览器界面验证

在本机回环测试服务加载实际 Vue 组件，用原创作品及隔离 IPC 替身验证。测试配置/替身仅在忽略的 `.artifacts`，不进入生产构建；它不证明真实官网或原生 IPC。

已实际操作的场景：

1. 从书架进入对应工作台，选章任务 1/1 完成时仍显示全书 1/3、缺 2 章。
2. 网页补齐、暂停、继续留在同一工作台，状态由后端快照更新；完成后转向导出。
3. 阅读、导出、切回阅读保留当前章节；正文修订后阅读区显示更新后的原创文字。
4. 导出显示对应作品路径与记录，选择 EPUB 后重新进入组件仍选 EPUB；无正文时导出禁用。
5. 起点目录确认直达工作台，所选第二个账户保留；保存页内改选账户后切换页签仍保留该账户。
6. 进入保存页/继续任务前仍要求本人核对官网与自动订阅设置，不能把窗口打开当成已登录。
7. 起点受限显示原原因、已存 1/3 和逐章的受限/待保存状态，默认不显示另建任务按钮。
8. 书旗仅目录作品无正文保存按钮，0/3 时导出禁用；键盘 End 切换末页签并保持正确焦点。
9. 新网页下载任务直接打开该书保存页；核心返回任务信息被人为延迟 1.8 秒时，用户主动切到书库后仍停留书库，迟到返回不强制导航。
10. 实测 760px：clientWidth=scrollWidth=745；390px：两者=375，无页面横向溢出，页签自身可横向滚动。临时视口已恢复。窄屏测试不代表移动端交付。

## 原生证据与用户限制

最终构建的独立副本使用 `.artifacts/workbench-20261026/native/library.db` 空白测试书库启动，实际观察到新添加界面，并通过导航进入空书库。辅助功能树和截图确认程序启动、界面资源及本地书库读取可用。

随后用户按下物理 Escape 停止 Computer Use，并明确要求“不要使用 computeruse”。从该时刻起没有继续调用 Computer Use，没有通过其他工具接管窗口、登录或操作浏览器，也没有强行关闭用户窗口。

因此，本轮**原生文件选择、导入直达工作台、阅读、TXT/EPUB 导出及格式重启记忆均未完成原生交互验收**。起点真实登录、权益失效、已购/未购差异及全书覆盖也未验证。以下 CLI 结果不替代这些门禁。
