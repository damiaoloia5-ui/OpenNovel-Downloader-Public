# v0.1.0 候选版验收记录

日期：2026-10-20。代码起点：干净的 `261921b`。本记录随首版功能提交；历史验证记录保留，不改写旧版本结论。

## 结论与范围

用户确认首版为“官网实际开放内容，缺章明确标注；App 正文后续扩展”，许可证选择 Apache-2.0。相应的下载、管理、离线预览、导出及 Windows 安装功能已实现，并进行了核心、真实来源和原生验证。

本轮生成了可用安装包，但 **AC-20 的独立干净 Windows 环境验收尚未完成**。当前机器没有 Windows Sandbox、Hyper-V 或现成虚拟机运行环境，未启用系统功能、创建操作系统账户或重装 Windows。本机全新安装目录、纯系统 PATH 和新 WebView 配置只证明本机安装与启动，不等于干净系统证明。因此交付状态为本地候选版，不能称全部发布门禁通过。

番茄网页访问范围仍是实验性适配，不能代表 App、账户或全站正文。七猫、书旗、起点、晋江未接入。

## 真实来源：最终核心实测

### 五章公开样本

作品 `7400799554502675518` 当前目录 5 章。隔离书库先用 `--chapters "1,3,5"` 得到 3/3 完成；再 `update` 补齐到 5/5。原三章任务导出仍为三章，书籍导出为五章。

正式标识的原生应用也读取同一官网目录，输入 1/3/5，任务显示 3/3 完成；从任务卡片导出 EPUB 后，检查 ZIP container、OPF spine 与每章标题：恰好对应选择的第 1、3、5 章，完整缓存中的第 2、4 章没有混入。三章任务完成没有把书库作品总数改成三章。

官网简介在新目录快照中保存；升级前的旧快照没有简介时界面显示“未提供简介”，不补造资料。时间字段明确标注为最近目录任务时间 UTC，不宣称正文出版时间或精确请求时间。

### 部分公开样本

最终 v0.1 CLI 重新下载作品 `7367780009773124632`：总计 47、保存 10、受限 37、失败 0、状态 partial，退出码 2。部分 EPUB 标注 10/47，文件名含 `partial-10-of-47`。这与此前 0.0.1 的历史结果一致，但本记录使用了最终核心重测证据。

真实采集的正文、书库及导出均保留在忽略目录或本机数据目录，不提交 Git。来源实现未使用第三方正文接口或真实账户。

## 原生安装、迁移与离线行为

实测系统为 Windows 11 家庭版中文版 x64，10.0.26200；CPU i9-14900HX，24 核 / 32 线程，物理内存约 31.8 GiB。应用标识 `org.opennovel.downloader`，界面由打包的 Tauri Release WebView 加载，非开发服务器。

1. 旧书库从 schema 3 升为 4，旁边生成 `library-v3-backup-*.db`。旧 6 本、20,018 章全部保留。
2. 原生导入新的原创 2,000 章样例，点击暂停，持久状态为 paused；继续后为 2,000/2,000。此前已完成的正文保留。早停和迟到提交边界另由核心并发回归覆盖。
3. 已有 10,000 章目录显示 100 项，翻页后首项为目录序号 101，页码 2/100。离线正文按保存的段落纯文本呈现。
4. 安装前额外用 SQLite backup API 保存当前书库到本地忽略目录。先确认没有既有安装，再静默安装到 `.artifacts/install-v01`；当前用户注册表版本 0.1.0，安装目录包含主 EXE、卸载器、Apache LICENSE 和依赖通知。
5. 用仅包含 Windows/System32 的 PATH 启动安装目录 EXE，无需 Node、Rust、Java 或开发工具 PATH。PE 导入检查只见 Windows / UCRT 系统 DLL，未发现 VCRUNTIME140 等额外导入。
6. 设置该进程 HTTP/HTTPS/ALL_PROXY 为不可用回环代理。首先读取官网目录确实报连接错误，然后原生本地预览和 2,000 章 TXT 导出仍成功，导出历史含路径及文件夹按钮。这是应用网络路径不可用的验证，没有禁用整机网络适配器。
7. 默认卸载后，本次独立安装目录中的程序被移除、卸载注册表项为 0；书库保持 7 本、22,018 章、schema 4。按作品/章节顺序计算正文行摘要，前后均为 `14db8ba32ca75ec7d4b6e345f0b4e41f57da945ee34312a00961dea1d7bf6876`，所有已登记导出路径仍存在。

默认卸载未勾选删除数据。生成脚本中的递归应用数据删除仅位于“删除应用数据”勾选分支，本轮没有执行该分支。安装器配置了 WebView2 downloadBootstrapper；本机已有 WebView2，缺失运行时的下载/安装分支未实测。包未签名，SmartScreen 及干净系统的依赖提示仍需独立验证。

## EPUB 与阅读器

EPUBCheck 5.4.0，Java 21，对最终导出的整本五章、三章任务、原创两章、原生三章任务及 10/47 部分样本校验：0 fatal、0 error、0 warning。XML 特殊字符与空作者另有自动化回归。

两款官方便携版阅读器使用项目原创《纸页之间》两章 EPUB，不分发远端小说正文：

- Calibre 9.16.0：实际 ebook-viewer 打开，中文标题和段落正确，PageDown 从第一章切换到第二章，顺序正确；WebEngine 截图及语义树留存。
- SumatraPDF 3.6.1 x64：实际打开 EPUB，左侧目录两章正确，中文段落正常；以 `-page 2` 打开后页码为 2/2、目录选中第二章且正文对应。定向窗口截图留存。

Calibre 便携解压器最初因最终路径超过其 59 字符限制弹错；改用 `.tools` 作为解压父目录，最终路径 58 字符，解压退出 0 后才进行阅读验收。这个错误属于验收工具，不是 OpenNovel 路径处理故障。

本地截图位于 `output/playwright`，测试目录、阅读器配置和工具不提交 Git。

| 场景 | 本机观测 | 证明边界 |

| 7 本、22,018 章，50 次书库 IPC | P50 20.6 ms，P95 23.2 ms | 原生 IPC + 书库快照；不是所有界面操作的 P95 |
| 同一库读取万章详情 | 约 93.1 ms | 含前置快照及详情 IPC，单次观测 |
| 独立 1,000 本原创元数据库，30 次 CLI 查询 | P50 25.4 ms，P95 27.8 ms | 含 CLI 新进程、开库与 JSON；不是千书 GUI 搜索基准 |
| 安装目录 EXE，新 WebView 配置启动 | 2,547 ms | 包含 CDP attach 与书库控件断言；同一 Windows 的系统缓存仍可能存在 |
| 应用 Rust 进程内存采样 | Working Set 约 41.4 MiB，Private 约 9.4 MiB | 不含 WebView 子进程，也不是峰值 |
| 安装包 / 原生 EXE | 3.93 MiB / 14.16 MiB | 未附带 WebView2 离线运行时 |

未将以上结果外推到低配置机器。导出仍物化一份正文快照，不能宣称内存与书长无关；导出中将已落盘文件登记到数据库失败，可能留下未登记文件，但不会删除已保存正文。全库大规模 UI 检索、长期压力、内存峰值和真实磁盘耗尽尚无完整基线。
