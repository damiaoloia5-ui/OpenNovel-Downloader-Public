## 已落实的代码保护

| 问题 | 实现与边界 |
| --- | --- |
| 多进程、多软件用户可叠加同平台访问 | core `TrafficGate` 按当前系统用户、固定平台键共享文件锁；GUI/CLI 公共 HTTP、账户自动保存、增强任务使用同一预算。书旗目录/正文域名映射同一键。锁由 OS 回收，不通过删除锁文件恢复。不同 Windows 用户、旧程序、手动网页操作及子资源不受该合作式锁约束 |
| HTTP 冷却仅在客户端内存 | 原子保存下次请求时间与冷却期限，读到损坏记录或持久化失败即停止；429/503 Retry-After、401/403/验证头立即记冷却。账户识别的受限/验证和增强限流/验证也写共享冷却；原按书库增强冷却兼容保留 |
| 停止与重启可能叠加剩余工作 | 增强适配器先销毁工作进程，再释放平台锁；原有限重试、取消与队列事务保持。账户整任务、增强整任务、公共 HTTP 单次含重试读取持锁 |
| 崩溃后官网临时目录残留 | 新会话使用随机 UUID、专用归属标记与生命周期锁；关闭、启动和新建时清理已失活受管目录。拒绝链接/目录联接与越界路径；保留活动、无标记旧目录和占用失败项。每轮最多检查 10000 个树内条目、删除 8 个会话，避免无界清理 |
| 原生检查未覆盖新保护 | `--check-installation` 加入真实文件锁、冷却持久化及受管会话检查，参与 required_checks_passed；仅受控临时数据 |
| 安装脚本只核对单书库 | 一次性 runner 脚本增加两位本地用户登记、第二用户原创导出与共享调度记录保留核验。原有运行环境和路径检查保留，拒绝在个人桌面安装/卸载验收 |
| 发布条件依赖散落文字 | `release_readiness.py` 检查六类同源码、同安装包哈希、14 天内证据。缺失、失败、时间/范围不匹配或以受控样本代替实际验收时阻止 readiness；它是证据台账工具，不独立认证人工陈述、不自动发布 |

没有新增依赖、改动数据库 schema、降低 SQLite 同步级别或修改正文完整性规则。TXT/Word/数据库仍是明文，软件内用户不是身份认证；这属于明确保留的数据模型边界，不写成已加密。没有实现验证码自动处理、付费权限绕过或避免平台识别的伪装措施。
