# 千书与万章离线基线

日期：2026-10-21；账户基础设施基线 f30d55d；应用开发版 0.2.0 / schema 8。机器为 Windows 11 家庭中文版 10.0.26200、i9-14900HX（24 核/32 线程）、约 31.8 GiB 可见内存。不是计划建议的低配参考机，不外推到所有 Windows 设备。

## 可复现的核心基准

新增 `crates/core/examples/performance.rs`，只生成原创内容，不连接网络。命令：

```powershell
cargo run --release -p opennovel-core --example performance -- .artifacts/performance-new-run
```

目标必须是不存在的新目录，已有目录会拒绝，不覆盖数据。生成 1000 部单章作品和 1 部 10000 章作品，总计 1001 本/11000 章；通过真实导入接口逐章事务保存，再测读取、TXT/EPUB、备份恢复。目录、JSON 输入和正文均受现有上限约束。原始结果保留在忽略目录。

| 测量 | 结果 | 范围 |
| --- | --- | --- |
| 千部单章作品导入 | 10.56 秒 | 含每部建任务与持久提交 |
| 万章作品导入 | 23.37 秒 | 10000 次逐章提交，不省略同步策略 |
| 核心全库快照 30 次 | P50 11.33 ms / P95 14.85 ms | 不含 IPC 或界面 |
| 万章详情 30 次 | P50 31.91 ms / P95 37.66 ms | 只加载目录元数据 |
| 单章读取 50 次 | P95 0.0048 ms | 已热缓存的核心调用 |
| 万章 TXT / EPUB | 263.5 / 724.1 ms | 单次，约 5.68 / 3.63 MiB 文件 |
| 全库备份 / 恢复 | 152.4 / 114.5 ms | 单次；全新目标目录 |

恢复后 11000 章的身份、顺序、标题和正文逐行 SHA-256 与原库相等；实际万章 EPUB 经 EPUBCheck 5.4.0 校验，0 错误、0 警告。构建例程前运行 fmt/clippy all-targets，通过。

## 原生界面

使用同一真实基准数据库打开 Windows 原生应用；不是浏览器模拟后端。冷重载界面后进入书架显示 1001 个作品卡片，万章目录只渲染当前 100 项。检查第 10000 章可读取。

| 测量 | 结果 | 方法 |
| --- | --- | --- |
| 进入千书书架 | 176.1 ms | 单次 UI 挂载，不称所有操作 P95 |
| 千书搜索 30 次 | P50 8.3 ms / P95 11.0 ms | 交替检索两个 10 项结果集合；input 事件到两次动画帧，核对结果数量 |
| 全库 IPC 30 次 | P50 20.4 ms / P95 27.7 ms | 核对 1001 本结果 |
| 万章详情 UI | 89.9 ms | 单次；等待目录显示并核对 100 项 |
| 浏览器网络设为离线 | 单章读取与万章任务 EPUB 导出通过 | 使用原生 IPC，不切断用户整机网络 |

UI 截图已检查。原始脚本首轮复用已存在的导出路径，被既有不覆盖策略拒绝；改用新的任务选章导出名称完成离线验证，没有删除或覆盖原 EPUB。测试还显式重载界面并等待异步目录结果，避免把旧筛选状态当作新视图结果。

原生 Rust 主进程：Working Set 34.16 MiB、Peak Working Set 46.39 MiB、Private 12.54 MiB。此记录不含 WebView 子进程峰值，不是完整进程树或长期内存上界；当前导出物化一份正文快照，因此不宣称内存与书长无关。后续仍需在低配机器、更多历史版本及长期运行下持续对照。

本轮为 NFR-02/03/09 和相关读取/备份场景提供基线；NFR-01 只覆盖上述指定交互，冷启动、强退/迁移和取消沿用各自验证记录，不能用本表替代独立干净 Windows 安装门禁。
