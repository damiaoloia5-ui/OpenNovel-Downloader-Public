# 起点官网登录入口修复

日期：2026-10-25。基线 main / d3e66ee，修改前工作区干净。未主动关闭或清理用户原有窗口及官网会话；本轮不提取正文，不读取或保存登录凭据。

## 问题与修复范围

原生窗口中已复现：软件“打开官网窗口”能够创建起点独立窗口，首页也能够加载；但首页“登录”和引导中的“立即登录”没有弹出登录框。软件未显示导航被阻止提示。点击官网已有的“我的书架”后，则正常跳转到“账号登录｜阅文集团”。

这证明了可用的替代流程，不代表已查明起点前端脚本内部的失效机制。因此修复软件的入口选择，不注入或修改官网 JavaScript，不把未证实的故障归因于网站封锁或域名限制。

- 核心增加固定起点登录入口 `https://my.qidian.com/bookcase/`，由官网执行正常认证跳转。起点空作品链接采用该入口；书旗仍为首页。
- 起点账户卡片增加“登录起点”，独立于作品链接字段；原有“打开官网窗口”仍严格校验作品链接。
- 同一账户继续复用其独立会话窗口；重新打开时显示、取消最小化并聚焦，不清空会话。
- 不扩大平台导航域名，不接受任意登录地址；不放开跨站 SSO、远程 IPC 或网页下载权限。账户能力仍为 open_unverified / can_download=false。

## 独立原生验证

使用 `.artifacts/qidian-login-fix-20261025/` 下的独立 release 目标目录和独立测试书库，没有覆盖原 release EXE。`tauri build --no-bundle` 成功，首次独立编译耗时约 4 分 11 秒。验证实例标题为“OpenNovel 登录修复验证”，启动时未设置远程调试端口。

通过原生界面实际操作确认：

1. 新建测试账户记录后出现“登录起点”按钮。
2. 作品链接字段填入无效跨站地址时，“登录起点”仍使用固定内部入口，正常跳转 `passport.qidian.com` 的“账号登录 | 阅文集团”页面，可见账号、密码和手机验证码登录入口；没有操作认证控件。
3. 重复点击“登录起点”后仍复用同一个官网窗口，窗口被显示和聚焦，没有新建第二个会话窗口。
4. “打开官网窗口”对同一无效跨站作品链接返回“只接受当前平台不含登录参数的官网作品链接”，没有导航到该地址。
5. 清空测试链接后，“打开官网窗口”也成功到达官方登录页，继续复用原窗口。测试链接已清空，官方登录页留给用户自行操作。

可运行文件为 `.artifacts/qidian-login-fix-20261025/OpenNovel-Login-Fix.exe`；同目录 `启动登录修复版.cmd` 固定传入独立测试书库。该产物是本地修复验证版，没有生成安装器、执行正式签名或发布。

## 验收边界

打开官方登录页、登录成功、确认已购权益、提取完整正文是不同阶段。本轮目标仅为修复进入登录页的路径。密码、扫码、验证码等认证步骤仍由用户本人操作；没有新增起点已购正文适配器，不承诺全书导出。原有用户会话不会因这次独立验证而主动关闭或清理。
