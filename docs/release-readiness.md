# 发布验收与剩余外部条件

本轮将可在代码内解决的风险落实为跨进程调度、持久冷却、受管会话清理和回归验证。没有取得平台授权、真实账号、独立系统或正式证书时，不能把这些条件写成通过。

## 运行保护

- 当前系统用户的数据根目录下 `traffic-v1/<平台>.lock/.json` 共享给本软件的所有书库、软件用户和进程。公共 HTTP 持锁完成一次含有限重试的读取；账户和增强持锁直到任务退出。后者会与该平台的公共读取互斥，其他平台不受该锁影响。
- 文件锁由操作系统回收，不通过 PID 猜测、锁文件年龄或删锁强行恢复。平台记录仅含两个时间值；写入失败或记录损坏时拒绝访问，不回退到无保护模式。
- 请求预算不覆盖不同操作系统用户、旧版本、手动官网浏览和网页子资源。账号是否被平台限制仍由平台规则决定；这不是绕过风控的功能。
- 新建官网会话使用 `session-v1-<UUID>` 和独立归属锁；关闭及下次启动尝试清理。清理前核对目录边界与整棵目录中的链接/联接；只回收自身标记且不在使用中的目录。旧版无标记目录保留，不能据前缀猜测后删除。文件占用导致失败时保留标记，下次重试；不作磁盘安全擦除承诺。
- TXT、Word、SQLite 和备份仍为明文文件。软件内用户是工作空间隔离，不是密码身份认证。不能以“不共享书库”宣传为“同 Windows 用户无法读取其他人的文件”；需要对本机其他人保密时使用独立 Windows 用户或系统提供的受保护存储，主动导出的共享文件仍按所选目录权限工作。

## 发布证据检查

运行 `python scripts/release_readiness.py --manifest <验收包内的 manifest.json> --output <新报告路径>`。工具不执行程序、不访问小说平台、不签名、不发布；任何缺失、失败、过期、来源/安装包不匹配的证据使退出码为 1。全部证据一致只表示可交给发布审核，不等于零风险或已发布。

清单与证据存放在私有验收目录，不提交账号记录、书名、正文、Cookie 或其他个人数据。清单格式：

```json
{
  "schema_version": 1,
  "version": "0.3.19",
  "source_commit": "实际完整的40位Git提交哈希",
  "installer": "OpenNovel-setup.exe",
  "installer_sha256": "实际安装文件的SHA256",
  "sources": ["local-json"],
  "evidence": {
    "engineering": {"path": "engineering.json", "sha256": "该证据文件的SHA256"}
  }
}
```

`sources` 必须是准备公开宣称支持的实际范围，不能用仅本地样本的清单发布全平台支持宣传。`evidence` 需要 `engineering`、`security`、`independent_windows`、`signing`、`licensing`、`platforms` 六项。每份证据包含相同的 `version`、`source_commit`、`installer_sha256`，以及 `kind`、布尔型 `passed`、含时区且距审核不超过 14 天的 `checked_at`、`checks`。每类必需检查项由脚本 `REQUIRED` 明确定义。

工程与安全证据需附原始检查、原生自检、资源清单、审计报告的位置与摘要，人工复核时逐一核对。安全项还要求漏洞库实际刷新成功，固定离线快照不能填写 `advisory_refresh_succeeded: true`。独立系统、平台、许可报告还需 `evidence_mode: "actual"`；平台报告的 `verified_sources` 必须与清单完全一致。不能将受控测试报告改成 actual。签名报告必须依据 `windows-signed-release.ps1 -Action Verify` 的实际验签结果，并核实安装器、主程序和卸载器；不能依据假签名契约测试填写。

本工具不能辨别人工伪造的验收陈述；证据来源、原始日志和签名信任链仍须独立复核。不要把清单通过称为自动化渗透测试或 CA 认证。

## 各项实际验收

1. **开发机**：`verify_project.py`、`verify_security.py`、原生自检和 AppContainer 验证；正文样本原创，完整保留失败和重试记录。
2. **一次性 Windows runner**：现有 `verify_installer.py` 只在 GitHub 托管 Windows runner 运行，安装、重装、卸载后核对原库、导出、多用户登记和共享调度记录。不能伪造环境变量在自己的桌面执行，也不将 runner 等同于干净消费者电脑。
3. **独立普通 Windows 用户/机器**：检查无 Node/Rust/Python、WebView2 缺失安装引导、安装/升级/重启/卸载、书库保留、休眠恢复与真实磁盘写满；保存安装包哈希和完整测试结果。本机临时文件夹隔离和写入失败注入不替代此条件。
4. **平台与权益**：只由本人在官网登录，无需向开发者发送凭据。分别记录目录范围、实际可读章数、保存/受限/失败数、导出完整性和持续运行结果；公开内容与真实已购权益分开验收，同时核对平台授权。没有已购内容时不得标注 VIP 全书通过。
5. **签名与许可**：CA/开源签名服务实际审核通过后签名并验签；核对应用许可证、引擎 GPL 对应源码及所有再分发材料。签名本身不代表平台授权或绝不触发 SmartScreen。

当前本地代码提交、签名证书申请、GitHub 推送和公开发布是不同动作。仓库规则要求 push/tag 另获明确授权；验收脚本不会代为执行。
