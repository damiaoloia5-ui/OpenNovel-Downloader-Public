# OpenNovel 使用指南

对应 0.3.10 Windows 一体化候选版，2026-11-02。先看 [第一次使用](QUICK_START.md)。未验收的能力见 [来源状态](sources.md) 与 [阶段清单](REMAINING_PHASES.md)。

## 默认自动得到 TXT

起点验证后恢复（2026-10-30）：请使用当前安装版或已更新的桌面快捷方式。出现滑块或导航变化时，“打开验证窗口”只恢复原窗口，保留验证页面。本人完成后点“我已完成验证，继续保存”；程序先检查已识别的可见验证提示、页面加载及会话/导航版本，失败不改变队列，成功才继续原任务。当前页已是待保存章节时不再重载，正文仍须通过身份、标题、长度和两次稳定读取。验证需要本人完成；默认建议改用标准 3 秒，可自行调整。实际官网/原生效果待本人验收。

默认只需粘贴链接、按提示操作、取 TXT。先退出旧程序，再从当前桌面入口运行，保留原书库。平台账号、来源、备份收进左侧“更多功能”；速度、选章和取消收进保存页的“更多设置”。

添加普通已支持网页链接后点击“开始保存为 TXT”，会自动识别平台、读取目录、选择全部标记开放章，创建保存任务并打开本书工作台。“只看获取范围”和高级选章保留。书旗或零开放章只显示范围说明，不启动无效任务；起点仍转到本人登录/目录/确认流程，不自动确认权益或购买。

桌面后台每秒检查轻量书库/任务快照，不依赖前端轮询、页面可见性或最小化状态。有正文且本书没有 queued/running 任务时，自动生成 TXT，包括完成、部分、失败、暂停、取消后的已有内容及启动时的已有书库。空书不生成；只重启页面不会新增同版本文件，后台也不请求正文或改变任务。正文修订和显式目录更新另外通知后台。

工作台顶部“自动 TXT 文件”显示保存章数、部分内容与错误，完整路径可展开查看，并可打开文件夹或重试。默认目录为该书库的 `exports/平台－书名－作者`；“本书保存位置”支持选择文件夹、手动输入已存在目录和恢复默认，按书记住位置并用于自动 TXT、作品/任务/历史 TXT 和 EPUB。文件名为 `平台－书名－作者.txt` 或 `.epub`，同名不同版本追加编号。更改位置只在新目录重新生成，不移动或删除旧文件。TXT 开头和 EPUB 的“作品信息”页包含来源提供的简介，缺失时明确标注；书名、作者、来源链接和章节覆盖情况同时保存。不同版本保留，未保存章不伪造。相同内容校验字节后复用记录；文件删除后在重启或显式重试恢复；目标内容被编辑则拒绝覆盖并要求先移走。文件落盘但记录写入失败时下次可校验并补记。

自动导出失败不改保存任务结果、不删书库正文；同一状态不每秒无限重试，需本人修复后明确重试或重启。状态提示在内存中，重启后从持久正文、任务与导出记录重建。CLI 原有下载/导出语义保持不变，自动后台是桌面功能，核心生成方法由两端共用。EPUB 和原手动导出继续可用，手动格式偏好不影响固定 TXT。

## 安装与首次使用

Windows x64 安装器按当前用户安装；不需要 Node、Rust 或 Java。运行需要 WebView2，一体化安装器附带 WebView2 离线安装程序。安装包未签名，其他系统与干净 Windows 尚未完整验收。

首次可先导入仓库的 `examples/local-book.json`，验证导入、离线阅读和导出。正式书库保存在系统应用数据目录 `org.opennovel.downloader`；CLI 默认使用当前目录的 `.artifacts/library.db`。不要让 CLI 和桌面同时打开同一书库。

## 获取公开内容

在“添加小说”粘贴官网作品链接，点“开始保存为 TXT”即可；想先核对范围时，展开“只想先看看能保存多少？”。番茄、七猫、晋江可下载经过验证的公开正文；书旗当前只读详情和目录。纯数字沿用番茄 ID；其他来源用 `qimao:ID`、`shuqi:ID` 或 `jinjiang:ID`。

默认选择全部标记开放章；需要选章时在高级预览中选择连续范围或填写 `1,3,5-8`。界面展示的是本次所选集合；“所选完成”不等于整书保存完整。网页不可读、VIP 或锁定项保留受限状态，不用预览片段填充正文。晋江可通过界面搜索，返回当前官网首屏最多 20 项，不是全站全文搜索。

“保存进度”中任务每页最多显示 20 项，可筛选进行中与暂停、失败/部分/受限、已完成任务。可暂停、取消、继续、查看逐章原因和只重试失败章。429 或临时网络失败会停止本轮请求，按提示等待后手动继续。受限章节不能直接强行重试，应先重新检查官网目录。

批次输入每行一个作品，最多 10 个输入；自动按来源和作品 ID 去重。默认每本前 3 章，也可指定集合。每次只执行一本；暂停后继续复用原任务，不另建重复任务。批次关联任务由批次面板统一控制。读取目录的在途请求可能等到有界超时后结束，停止后迟到结果不会创建新任务。

## 作品工作台

选择“只看获取范围”后展示目录标记开放数、目录受限数；来源未开放时显示待验证数，不因 restricted=false 声称免费。“仅保存目录标记开放章”一次选择全部开放标记位置，跳过目录明确受限项；自定义范围继续保留，可明确记录所选受限章。实际开放状态以获取结果为准，目录不是阅读权益证明。没有自动购买、广告解锁或自动寻找第三方正文。

“书籍详情”和“保存进度”中的“为什么有些章节没保存？”提供缺章原因与下一步，从核心详情读取逐章依据：本地已有正文优先，其次来源能力、最近确认目录及每章最近任务。后建的小范围任务不抹除其他章节的错误。分类包括访问受限、获取失败、等待、暂停、取消、未尝试、来源未开放与待核对；保留原始错误而不从关键词推断登录或订阅。明细每页 50 章，支持类型与标题/序号筛选，并链接到原任务。只读报告不请求官网，不改变任务状态或原书库正文；旧记录无依据时明确待核对。

从书架点击“查看进度与正文”，一本书的保存、阅读和导出都在这里完成。新下载/导入任务创建后直接打开对应作品；起点核对书名和阅读权限后直接开始保存，并进入工作台，保留选定账户。重复粘贴已有小说回到原进度，不创建重复任务。

- **书籍详情**：显示书库实际保存数和下一步。只保存所选章节时，即使任务完成，整书仍显示缺章。
- **保存进度**：起点使用本书账户官网窗口；已支持网页来源可检查目录并补缺章。暂停/继续、任务记录和逐章原因在同页，批次任务仍从全局任务面板统一控制。失败或受限时优先继续原任务，另建任务放在高级选章选项中。
- **阅读正文**：默认只列出已保存章节，可检索或切换全部目录。同一工作台切换页签保留当前章节，更换作品或关闭软件后不承诺恢复阅读位置。
- **其他格式与文件记录**：选择 TXT / EPUB、生成文件和打开目录；下方保留本书导出记录。格式记忆仅保存界面偏好，不保存账户凭据，不改变书库或默认导出目录；系统禁止界面存储时仍可本次导出。

键盘聚焦页签后，可用左右箭头切换，Home / End 到首尾页签。标签、归档、目录变更及历史版本保留在书籍详情的高级操作中。

## 书库、阅读与导出

书架每页最多显示 48 本，底部可切换首页、上一页、下一页和末页。搜索书名、作者或标签会检索全部作品并回到第一页；可切换书架/已归档/全部。详情中修改逗号分隔的标签和归档状态；这些本地字段不随来源更新覆盖。归档不删除正文。

目录按每页 100 项显示，可检索并预览已保存章节。TXT 为 UTF-8，EPUB 为 EPUB 3。书库导出包含该书全部已存正文；任务导出只包含该任务选择的集合；缺章会标为部分内容。同名文件已存在时会明确提示并保留原文件；可从详情中的导出记录打开原导出，或使用 CLI 的 --output 选择其他目录。重复导出不会新增记录。

“检查更新并补齐”自动处理不变目录和末尾新增；若出现删章、重排或插章，打开“目录变更与历史版本”先预览，再明确确认。确认会保存旧快照，10 分钟后预览过期需重新读取。该书有待执行或暂停任务时，先完成或取消任务。

选择已保存章节后，可检查该章正文修订。实际变化才保留旧文并更新；网络失败、取消、标题或身份不一致均保留原文。历史快照可查看旧章并导出。界面显示最近 20 个快照，更多记录可用 CLI；不自动清理历史。

## 备份与恢复

“备份与诊断”中创建一致性备份，程序给出包含 manifest 和数据库的目录。备份包含书库、任务、标签、修订历史、导出记录与非敏感账户别名；不复制导出文件、浏览器会话或凭据。

填写该备份目录恢复时，先校验 SHA-256、完整性、版本与数量，再恢复到全新副本。成功后可打开独立窗口；不会替换当前书库。外部导出文件可能仍指向原位置，可从恢复副本重新导出。

当前书库 schema 9；从旧版本首次打开前自动生成迁移备份。恢复到独立书库时会清除各书的自定义输出目录，避免写入原书库的位置，需要时可重新选择。迁移前自动备份和手动备份都应另行保存到可靠存储。旧程序不能直接打开较新的 schema；需要恢复兼容备份到独立目录。卸载器默认保留数据；选择“删除应用数据”前请先备份。

## 平台账户实验

提供起点四步保存引导和书旗临时官网窗口。起点点击“打开官网登录”，通过官方书架正常跳转登录页，不依赖首页登录弹层。软件只报告窗口打开，不自动判断已登录。多个本地账户可在页首切换。

填写不含登录参数的起点作品链接后，使用“打开作品目录”查看作品；“高级操作”中的书旗入口打开官网首页。请在官网本人完成登录，不要把密码、验证码或 Cookie 填入本软件或问题报告。

不同账户使用独立临时浏览器环境；关闭窗口结束会话，下次需重新登录。“关闭并清理会话”先清理本机浏览数据再关闭，移除记录保留书库。当前不提供自动登录检测、凭据持久化或其他设备退出。起点提供当前页保存和自动逐章保存实验；真实已购权益与 VIP 全书覆盖尚待用户本人配合验收。

### 起点：自动保存全书（实验性）

1. 粘贴起点作品链接，点“开始保存为 TXT”。
2. 点“打开起点，去登录”，在官网完成登录，再回软件点“我已登录，下一步”。
3. 软件自动打开目录并尝试读取，最多 6 次；如未读到，按提示在官网展开全部章节或处理验证后，点“我已处理，重新读取”。
4. 核对书名、章数和首末章，本人在官网关闭自动订阅，勾选阅读权限确认后点“是这本，开始保存为 TXT”。软件直接开始保存并进入本书页面，无需再次找保存按钮。
5. 保持官网窗口打开，不手动翻页。可暂停；下次从书库打开，按提示登录后继续保存。
6. 保存结束或暂停后自动生成 TXT。点“打开 TXT 所在文件夹”；书架也提供 TXT 文件夹入口。

窗口状态不证明登录或阅读权益。目录重试只针对有界的加载/目录识别错误，遇到验证、订阅、会话变化或超长结果立即回到用户处理。账号/链接变化或离开页面时，迟到结果不会自动确认或开始保存。目录确认成功但开始任务失败时保留目录，直接在保存页重试，不要求重复读取。

速度、选章和取消在“更多设置”；手动逐章读取和账号管理在起点页底部的“更多设置”。未保存内容继续标注缺章。

自动会话任务只从桌面账户入口启动或继续，CLI/普通 HTTP 入口不能运行。同一时间只执行一个官网自动任务，默认极速节奏最小翻页间隔 0.5 秒（实验），可选快速 1 秒、标准 3 秒或缓慢 6 秒，单章最多 30 秒。节奏在启动/继续时生效，运行中需要先暂停再改；旧客户端省略节奏仍使用 3 秒。每章仍等待页面 complete，再执行相隔 400ms 的两次一致读取。真实 VIP 全书仍待本人配合验收，不能保证所有订阅作品都能保存。

公开网页默认请求起始间隔从 1 秒调整为 0.5 秒；可通过启动环境 `OPENNOVEL_HTTP_INTERVAL_MS` 在 250～60000 毫秒内调节，无效值回退 500。仍为串行完整正文处理，不并发操作账户窗口。服务器 429 / Retry-After 优先，不能以快速节奏覆盖退避；验证、付费提示及异常仍停止。快速模式可能更早触发平台限流，遇到时请改慢并处理官网提示。

1000 个未保存章节的起点极速节奏下限约 8.3 分钟（快速 1 秒档约 16.7 分钟）；这只是忽略页面加载等耗时的推算，不是全书实测或完成时间承诺。已保存正文仍跳过。网络、页面渲染和平台限制可能占据主要耗时。单次提取缓存仅存续于当前同步读取，相同正文的第二次确认复用首次校验结果；页面变化仍重新检查。使用本轮“启动简明版.cmd”打开原书库，旧快捷方式可能仍指向旧程序。

### 起点：保存当前可读章节（实验性）

1. 按上方引导打开官网登录与作品目录，再展开页面底部“更多设置”中的“保存当前可读章节”。
2. 在同一官网窗口切到目录，展开全部章节。回软件展开“保存当前可读章节”，点“读取完整目录”，核对书名、作者、章数后“确认保存完整目录”。未完全加载时会报错，不写入局部目录。
3. 在同一官网窗口手动打开你有阅读权限的一章完整正文。回软件点“预览当前章”，核对标题、正文首尾，再点“确认保存当前章”。不要在读取过程中切换页面。
4. 重复步骤 3 保存其他章节。可从“在书库查看”离线阅读，也可“导出已保存 TXT/EPUB”；未存章节会显示缺章提示，未收齐不标成完整。

仅识别 `www.qidian.com/book/数字/`（含 `/catalog/` 目录页）和 `www.qidian.com/chapter/书号/章号/`。其他阅读地址、未知结构、未购提示、试读截断、保护字形或尚未加载完整会拒绝保存，不需要提供 Cookie。预览 10 分钟过期，关闭账户窗口后需重新读取。同章重复保存不会产生重复任务；内容不同时拒绝覆盖。当前只接受目录末尾增章，目录重排应先保留原书库等待后续适配。

目录解析、字数检查和用户预览仍不能代替真实逐章验收。自动翻页使用上面的独立入口；手动保存仍可用于逐章核对。可读页面能否成功保存，要以实际作品和页面结构为准。

## 诊断和问题报告

先预览诊断 JSON，再决定保存分享。固定内容只有版本、系统、schema、数量、任务状态和完整性布尔值，不含书名、正文、路径、标签、账户与网络错误原文。问题报告建议包含版本、来源、公开作品链接、操作步骤和可复现现象，不附数据库或完整平台正文。

## CLI 补充入口

运行 `opennovel --help` 查看所有命令。使用源码时将前缀替换为 `cargo run -p opennovel-cli --`。以下 ID 均替换为本机实际返回值；目录选择全新的路径。

```powershell
opennovel --database .artifacts/library.db search 书名 --source jinjiang-web
opennovel batch book-links.txt --chapters "1,3,5"
opennovel batches
opennovel batch-resume BATCH_ID
opennovel organize BOOK_ID --tag 收藏 --tag 连载 --archived
opennovel backup D:/NovelBackups/new-backup
opennovel restore D:/NovelBackups/new-backup --output D:/NovelRestored/new-copy
opennovel diagnose
opennovel diagnose --output D:/NovelReports/new-diagnostic.json
opennovel update-preview BOOK_ID
opennovel update-accept BOOK_ID --previous-hash PREVIOUS_HASH --proposed-hash PROPOSED_HASH
opennovel refresh-chapter BOOK_ID CHAPTER_ID
opennovel history BOOK_ID
opennovel read-history SNAPSHOT_ID CHAPTER_ID
opennovel export-history SNAPSHOT_ID --format epub --output D:/NovelExports/new-folder
```

`update-accept` 要求与先前预览一致的前后摘要；本地或官网已变化时拒绝。`organize` 未加 `--archived` 表示回到书架；标签以本次指定集合替换。CLI 不控制另一进程中的任务或账户窗口。
