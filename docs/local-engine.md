## v0.3.4 首次使用与恢复，2026-11-01

增强检查区新增“下一步”，用固定故障类型区分未找到 Docker 程序、服务未就绪、Windows 容器模式、待首次导入、导入失败和组件校验失败。软件不根据陌生错误文本推断安全性或执行修复命令；未知结果保守显示检查未完成。故障状态仍保留先前的主动启用选择，不能把记住选择视为已就绪。

已记住但未就绪时，提供“重新准备本地增强”；无论组件是否完整，都可“关闭并忘记选择”。只读重新检查不会启动服务或导入镜像。准备和检查使用不同等待提示，忙碌时阻止重复操作；离开页面后忽略迟到结果。检查报告也附故障类型和下一步，原生安装自检不启用增强、不打开用户书库。

维护者生成的资源目录改为 `.artifacts/integrated-resources-<版本>/opennovel-engine`，不同候选版本分别保留；Tauri 打包配置需指向相同版本。独立引擎镜像、源码归档及免费范围未变，不需要重新构建上游引擎。见[本轮验证](verification/2026-11-01-guided-recovery.md)。

## v0.3.3 离线组件版，2026-11-01

1. 关闭旧窗口，双击桌面 OpenNovel 快捷方式。
2. 粘贴番茄作品详情链接，点“开始保存为 TXT”。
3. 首次按提示启用增强。软件核对内置文件，必要时启动已安装的 Docker Desktop，并从本地包准备引擎；无需自行下载镜像、配置 Python 或构建。完成后自动生成 TXT。

首次准备可能需要几分钟，之后按书库记住选择。继续已暂停的本地引擎任务时，软件也会尝试恢复所需组件。关闭增强会使旧的准备结果失效；取消准备中的任务不会在准备完成后开始保存正文。镜像导入是 Docker 后台操作，取消后仍可能完成缓存导入，但不会因此写入正文或重新启用选择。旧正文、任务和 TXT 保留。

仍需 **Docker Desktop 的 Linux 后端**。软件不安装 Docker，不修改虚拟化，不要求用户手工创建开发构建卷。当前组件仅验证 Windows x64 与 Linux amd64 镜像，不代表干净系统或其他架构通过。

一体化包包含固定 Python、9 个运行文件（含锁定清单）、约 45 MB 的运行镜像归档和约 34 MB 的完整对应源码归档。两个归档与清单在运行前按程序内固定字节/摘要检查；不允许清单自行指定其他程序或远端下载地址。准备时仅本地 `docker image load`，就绪后按固定镜像 ID 使用；无开发卷回退。

独立引擎作为 GPL-3.0 组件提供，对应源码在 `opennovel-engine/offline-engine/corresponding-source.tar.gz`，含上游、封装、228 个 vendored 依赖、许可证及 `REBUILD.py`。Apache-2.0 主程序和第三方组件分别保留许可。

维护者准备流程：固定上游来源后，运行 `scripts/prepare_engine_sources.py --download-missing`（仅维护者显式补齐锁定 crates.io 归档）；运行 `scripts/build_offline_engine.py --revision <新编号>`，在无网容器构建并生成新分发目录。审查构建、许可、摘要与对应源码后，更新 `engine_bundle_lock.json`，再运行 `scripts/prepare_integrated_component.py` 和 `npm run desktop:package:integrated`。应用不会执行这些构建或下载步骤。升级需准备全新资源目录并保留旧版，不拼接不同版本组件。

本轮受控首次导入、原生 TXT、恢复及来源复验以[验证记录](verification/2026-11-01-offline-engine.md)为准。只处理明确免费的正文，不扩大 VIP 或其他平台支持。

## v0.3.2 一体化版，2026-11-01

日常使用不再需要配置 Python、环境变量或启动脚本：

1. 关闭旧窗口，双击桌面 OpenNovel 快捷方式。
2. 在“添加小说”粘贴番茄作品详情链接，点“开始保存为 TXT”。
3. 首次按提示启用本地增强。软件检查资源，必要时尝试启动已安装的 Docker Desktop，随后保存明确免费且通过校验的章节；完成后打开自动 TXT 文件夹。

选择按当前书库记住；以后直接粘贴链接保存。可在“番茄本地增强已启用（已记住）”中关闭。环境暂时不可用不抹掉选择和既有正文。第一次从网页结果切换本地来源，会重新核对目录；已有网页版本保留。

一体化包包含固定官方 Python 3.14.10、完整标准库/运行文件、7 个已审查脚本、候选源码和许可证。组件从 EXE 相邻 `opennovel-engine` 自动发现，不搜索当前工作目录或任意网络地址；Python 与脚本在运行前按程序固定清单核对，发现改写或多余文件则拒绝。

**仍需系统隔离环境**：Docker Desktop Linux 后端、固定镜像及已有构建卷没有被打进安装包，也不会自动安装、拉取或修改系统虚拟化。启动已安装服务失败时，软件明确提示；缺少镜像或固定构建时仍需维护者准备。它不是全依赖离线安装包，也不能把本机结果当作另一台干净电脑的证明。

维护者先运行 `python -B scripts/prepare_embedded_python.py --download`，核对官方发布 SHA-256；再运行 `python -B scripts/prepare_integrated_component.py`，最后 `npm run desktop:package:integrated`。首次下载为维护者显式行为，应用启动不下载 Python。资源目录存在差异时拒绝覆盖，需先保留旧目录并准备新资源；不递归删除。

软件内状态检查和 `--check-installation <绝对输出目录>` 均不打开用户书库、不请求小说正文。主动启用或用户已记住选择后点击保存，才可能尝试启动已安装的隔离服务；普通状态检查不会启动它。安装检查仍使用原创两章。

仅明确免费的本地组件样本已在前一版本实测 102/102 章；本轮着重验证一体化发现、恢复选择和原创样本链路，未扩大多平台/VIP 支持。见[一体化验证记录](verification/2026-11-01-integrated.md)。

## 普通操作

1. 启动配置好组件的新版桌面程序，进入“添加小说”。
2. 粘贴番茄官网作品详情链接，点击“开始保存为 TXT”。
3. 网页目录存在受限章节、组件就绪时，点击“启用本地组件，保存更多免费章节”；软件重新读取目录并保存明确免费的章节。也可展开“番茄网页只保存了前几章？本地引擎实验”查看状态并启用。每次重启默认关闭。
4. 在作品工作台查看进度；已存正文保留，暂停后继续原任务只补缺章。停止或完成后，由现有自动 TXT 服务生成文件。
5. 看到付费、验证或完整性错误时查看原因，处理后再继续。软件不自动购买、注册设备、轮换身份或处理滑块。

新引擎使用独立来源 `fanqie-app-local`，与 `fanqie-web` 分别入库，不自动合并已有网页版本。关闭组件前先暂停任务并等进程清理完成。关闭后仍可阅读、导出已有正文；再次续存需重新启用。

## 维护者准备环境

这是本机开发组件，支持独立准备目录和原有源码树两种布局；不从当前目录或网页下载并执行脚本。Python、Docker、固定镜像及构建卷仍为外部依赖，单独复制 EXE 到另一台机器不能获得此能力。

- Windows、项目现有 Rust/Node 构建环境、Python 3.12+、运行中的 Docker Desktop Linux 后端。
- 先按[隔离评估](research/local-engine-admission-20261101.md)固定候选源码、inventory、镜像和依赖缓存；不要运行来源不明的 Windows 成品，也不要使用候选设备补齐/权益入口。
- 候选固定 `ch6vip/fqapp` 提交 `07cfb2249d4fd57d19bf4420af0e97621ec92df9`，GPL-3.0。候选仍独立构建，未复制进 Apache-2.0 主程序。本预览没有打包分发候选二进制；未来分发前需落实其对应源码、许可和通知义务。
- 运行 `python -B scripts/research/run_local_engine_gate.py` 完成离线构建与门禁，确认固定 target volume 中存在 `opennovel_engine_service`。
- 在启动桌面程序的同一个 PowerShell 中配置 Python 可执行文件的绝对路径（请换成本机安装路径）：

```powershell
$env:OPENNOVEL_ENGINE_PYTHON = 'C:\Python312\python.exe'
& $env:OPENNOVEL_ENGINE_PYTHON -B scripts/research/desktop_engine_worker.py --check
npm run desktop:dev
```

状态检查只验证固定源码哈希、本地镜像、只读构建及 Docker 可用性，不向小说平台请求正文，不自动安装依赖或拉取镜像。不需要填写 API Key、Cookie 或账户凭据。依赖缺失时只禁用引擎，普通网页功能保持原流程。

### 独立准备目录（推荐用于本机预览）

先完成固定构建和桌面 `npm run desktop:build`，再使用当前 Python 准备一个**尚不存在的绝对目录**：

```powershell
python -B scripts/prepare_local_engine.py --output 'D:\OpenNovel-Engine-Preview' --executable target/release/opennovel-desktop.exe
```

工具先核对已有候选源码，再复制 7 个运行脚本、完整候选源码及其许可证、校验清单和可选 EXE。不会拉取镜像、请求章节、执行候选或覆盖已有目录。复制失败时保留现场，不自动递归删除输出。候选 Linux 二进制不在复制目录中，仍使用本机预先构建的只读 Docker 卷。

双击新目录中的 `Start-Isolated-Preview.cmd`，启动脚本仅设置进程级 `OPENNOVEL_ENGINE_PYTHON` 和 `OPENNOVEL_ENGINE_ROOT`，并使用该目录的独立 `preview-library`。程序启动后仍需主动启用引擎，不更改现有快捷方式、系统设置或原书库。

程序按本次 EXE 构建嵌入的字节核对全部运行脚本，并拒绝额外脚本、子目录或被改写的脚本；`component.json` 只是校验记录，不能授权任意代码。升级脚本或程序后请重新准备一个新目录，不能拼接不同版本。清单及源码校验不构成对 Docker 卷内二进制或整套依赖的全面安全证明。

双击 `Check-Installation.cmd` 可运行同目录 EXE 的 `--check-installation <绝对输出目录>`。每次创建新检查目录，验证 WebView2 和原创两章入库/自动 TXT，并报告可选组件是否就绪；不启用组件、不打开用户书库、不请求商业平台、不拉取镜像。退出码 0 为基础检查通过、1 为检查失败、2 为参数或报告写入错误。`report.json` 明确区分基础检查与可选组件；基础通过不能视为真实窗口、付费权益或独立系统验收。

不需要继续读取原开发目录内的运行脚本或候选源码，但仍依赖本机 Python 安装和 Docker 环境，因此该目录不是通用离线安装包。最新准备验证见 [本轮记录](verification/2026-11-01-prepared-component.md)。

## 实现与限制

桌面后端在进程内复用 `Library`，避免伴随程序再次打开同一数据库锁。Python 仅负责生产章节信封；核心独立验证身份、标题、免付费状态和字数后事务提交。前端不接收原始引擎 HTML，也不负责抓取和导出。

每个任务懒启动一组无网容器，连续章节复用进程。只有宿主固定 HTTPS 门禁可以向已审查的官方目的地发送限定 GET；不接受任意 URL、重定向、凭据或写操作。候选不挂载书库、浏览器数据或 Docker socket。

JSON 行大小、编号、身份和读取等待均有上限。取消/EOF 通知 worker，丢弃迟到结果并清理本次精确容器；容器自动删除，relay 空闲退出。Docker daemon 故障、宿主强杀或 created 状态的极小崩溃窗口仍可能需要维护者检查，不能保证所有系统故障下零遗留。已经发出的 HTTP 请求可能继续到既有 I/O 期限，结果不会入库。

限流、访问挑战和正文异常即停止，不自动切换服务；仅短暂空响应、连接失败或特定服务端错误最多尝试两次，并受取消和时间预算约束。不容许正文少于声明字数；长篇完整文档允许极少的新增字符，原样保留文字，其他完整性校验不变。真实多作品覆盖、原生窗口交互与独立安装交付仍需后续实测。
