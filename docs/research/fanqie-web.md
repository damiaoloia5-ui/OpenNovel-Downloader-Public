# 番茄官网网页来源研究

实测日期：2026-10-20。状态：实验性，第一版尚未验收。实现由 OpenNovel 独立编写，不复制参考项目代码或字体映射。

## 真实路径与边界

- 作品页：`https://fanqienovel.com/page/{book_id}`。
- 阅读页：`https://fanqienovel.com/reader/{item_id}`。
- 读取网页里的 `window.__INITIAL_STATE__` 对象。只解析数据并处理字符串外的 `undefined`；不执行网页脚本。
- 分卷列表决定阅读顺序；`itemIds` 经实测可倒序，只用于校验目录身份集合，不拿其顺序覆盖分卷顺序。重复 ID、索引遗漏或字段变化会中止任务创建。
- 目录及正文均检查 `needPay`、`isChapterLock`，并处理付费出版/故事标记。目录标记受限的章节不发正文请求。
- 正文要求作品/章节身份一致、已知字体版本、可识别字形、有效段落与合理长度。长度为声明字数的 80%～150% 是保守异常检测，不能证明与作者原稿逐字相同；还需扩大人工对照样本。

| 官方样本 | 目录 | 本轮结果 | 能证明的范围 |
| --- | --- | --- | --- |
| [7367780009773124632](https://fanqienovel.com/page/7367780009773124632) | 47 章 | 10 章保存、37 章网页受限 | 免费作品不等于官网网页提供全部正文 |
| [7400799554502675518](https://fanqienovel.com/page/7400799554502675518) | 5 章 | 5 章保存 | 该样本当前目录完整获取；不能推导为其他作品或未来更新均可获取 |

第一个样本的第 12 章网页实测返回约 200 字符 HTML，而声明字数为 1366，并带网页锁定标记。该返回被拒绝，不能作为完整正文。没有调用第三方解析服务、账户接口或客户端私有接口。

## 字体还原的方法与来源

官网正文使用私用区字符并由字体显示实际汉字。直接提取页面文本会保存乱码。研究下载了页面公开引用的字体，检查其字体元数据，再与对应版本的 Adobe 思源黑体逐个比较字形轮廓。

官方资源：

- [官网字体 WOFF](https://lf6-awef.bytetos.com/obj/awesome-font/c/dc027189e0ba4cd.woff)。
- [Adobe Source Han Sans 2.002R 文件](https://github.com/adobe-fonts/source-han-sans/blob/2.002R/OTF/SimplifiedChinese/SourceHanSansSC-Normal.otf)。

使用 fontTools 4.67.0 的 RecordingPen，将轮廓操作和坐标（四位小数）作为比较键；在官方原字体的 ASCII 及基本汉字字符中寻找唯一对应。362 个字形全部唯一匹配，无猜测补齐。项目只保存字符对应关系及哈希，不包含字体文件或采集小说正文。

| 输入 | SHA-256 |
| --- | --- |
| 网页 WOFF | `ba1a867e395a7f8bca99dd13a0d6428b8f12fc9c38e3a0b2c3522b98f41763fe` |
| Adobe OTF | `69a090057ee75936451397c038da6d32194e45bbf878ef674dddc0d5f0621ce5` |

复现：安装开发依赖 `fonttools==4.67.0`，下载上述两个原始文件，在根目录执行 `python scripts/research/match_fanqie_font.py <woff路径> <otf路径>`。输出可与 `crates/core/src/sources/fanqie_font.json` 比较。运行软件无需 Python 或 fontTools。

下载前核对实际 WOFF 哈希，正文页还需引用已知字体路径。字体变化或未知编码会失败，避免静默保存乱码。新版本字体需要重新研究并通过原创编码样例和实际网页对照后更新映射。

## 网络、保存与恢复

HTTPS 与固定域名白名单，重定向最多四次；禁用任意外部来源输入。每个客户端请求起点至少间隔一秒，连接超时 8 秒，总请求超时 20 秒；目录最大 8 MiB、正文最大 2 MiB、字体最大 512 KiB（解压后上限）。429 后停止当前运行，遵守数值型 Retry-After（上限一天）；其他格式暂按 60 秒，需手动继续。未做自动重试风暴。

取消在调度等待、响应读取后与数据库提交前检查；正在进行的阻塞 HTTP 不会立即中止，最坏还要等待本次 20 秒超时。前端通过后台线程调用，不阻塞窗口。多个桌面任务共用客户端预算；多个独立 CLI 进程的请求预算尚未跨进程协调。

目录先持久化，网络请求不占用数据库锁。正文与章节完成状态同事务提交。网络失败停止新请求并保留已存章节，继续时只请求缺失项。范围完成与整本覆盖分开统计；受限章节不会增加成功数。目录身份或顺序变化时保守拒绝新下载，增量更新另行实现。

SQLite schema 1→2 升级前使用 SQLite 在线备份 API 在原书库旁生成唯一命名备份，然后事务添加目录表及任务索引。备份失败不继续迁移。不覆盖已有导出文件，部分导出文件名包含保存数量与目录总数。

## 第一版剩余门槛

扩大长短篇、完结/连载、分卷及不同字数样本；逐章失败明细、动态目录增量、立即中止 HTTP、离散选章、暂停语义、Windows 安装和干净环境验收仍需实施或增强。网页受限的广泛作品覆盖仍是首要问题。不能将这次实验性接入标为“番茄全站可下载”或 v0.1 已完成。
