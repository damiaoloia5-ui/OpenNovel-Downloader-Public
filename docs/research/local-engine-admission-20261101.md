# 可选本地引擎准入评估：阶段一

日期：2026-11-01。OpenNovel 修改前基线 174fad7。用户已明确同意评估经过审查的开源本地引擎，保持独立、默认关闭，不使用陌生公网解析服务。本轮完成固定版本源码取证、局部准入审查和断网容器验证，未完成全面安全审计或正式集成。

## 结论

候选 `ch6vip/fqapp` 的 Rust 核心具备可研究的本地调用与受控协议处理能力，但**当前不准入联网正文获取或桌面默认功能**。允许继续设计独立的最小只读封装。不能将以下测试当作安全认证、正常官方协议已复现或番茄完整小说下载成功。

本轮没有复制参考成品的代码，没有将候选源码、签名算法或内置常量并入 OpenNovel 业务代码，没有运行候选 Windows 程序，也没有进行真实账户、设备注册、权益申请或章节请求。

## 实际隔离验证

本机 Docker 客户端存在但后台未运行。已通过 CLI 启动现有 Docker Desktop，未安装或调整虚拟化/安全配置，未使用 Computer Use，未操作其他项目容器。验证缓存保留在本轮两个命名卷中；没有清理其他镜像、卷或容器。

使用 Docker 官方 `rust:1.96-slim-bookworm`，本轮镜像标识为 `sha256:e18a79fc84dfcfc3ab5ba72290398a644c135c97eaa881447fddc354ee4701a3`。创建容器后读取 Docker inspect 核对配置，再执行：

1. 仅初始化两个专用缓存卷。此容器无网、只读根目录；使用 root 和额外 CHOWN 能力只为设置卷所有权，不执行候选代码。
2. 非 root 容器运行 `cargo fetch --locked --target x86_64-unknown-linux-gnu`，下载锁定依赖，不运行候选构建脚本。此阶段允许联网下载 registry 依赖，不声称 bridge 网络自身具备域名白名单。
3. **候选构建与测试阶段**固定 `--network none`、`--read-only`、`--user 10001:10001`、`--cap-drop ALL`、`no-new-privileges`、2 CPU、2 GiB 内存、256 进程上限。仅将候选源码只读挂载到 `/src`，使用独立 cargo/target 卷和临时目录；不映射端口，不挂载 Docker socket、浏览器、账户、真实书库或用户目录。

候选代码从未在有外网的容器内执行；依赖下载阶段与实际执行阶段的容器配置均留有 inspect 证据。容器级隔离不等于不存在内核或运行时漏洞，本轮没有做容器逃逸审计。

| 原始测试目标 | 结果 | 解释 |

| `loopback_guard` | 12 通过、1 失败，退出 101 | 原样保留失败；没有通过放开外网或修改候选源码让它通过 |

失败为 `loopback_guard.rs:483` 的 LAN 用例：辅助函数 `lan_loopback` 在第 412 行使用 `mock_origin=None` 和 3 个测试设备；随后提交带会话能力的评论写请求。设备不足会触发补齐，缺少 mock 时走真实上游分支。断网下返回 500，断言预期 200。此结果揭示该用例的外部依赖，也证明不能因为路由看起来是本地便开放执行。没有向外部平台发出这些请求；不能把它解释成真实平台注册服务故障或 Windows 连接问题。

## 下一步的最小只读封装

继续评估的边界已经明确，无需再次询问用户是否接受评估：

1. 独立、默认关闭，不直接将 GPL 核心链接到主程序或复制进业务源码。
2. 明确列出允许的查询/章节读取操作；封装内部和网络出口同时阻断设备注册、权益申请、账户、评论、媒体和任意 URL。禁止默认 `full`/批量分支自动回退。
3. 会话能力、进程归属和组件版本均可核对；只读元数据也需要本项目自己的访问控制。
4. 先用受控 broker 记录所有出口并验证拒绝路径；未满足此项不进行真实免费章节请求，不因 GUI 按钮写着“只读”而省略内部副作用检查。
5. 最后再验证正常权限下的免费完整章节、目录/身份和原文一致性，合格后才进入 OpenNovel 的事务保存与 TXT 流程。

当前完成的是候选的阶段一评估。暂不创建可供用户启用的“本地全文引擎”选项，不更换桌面快捷方式或安装包，不扩大番茄/VIP 来源支持。
