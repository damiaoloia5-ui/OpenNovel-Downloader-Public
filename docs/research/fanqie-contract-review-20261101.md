# 番茄客户端调用契约复核与传输验证

日期：2026-11-01，修改前基线 db74d67。延续[单章探测原型](fanqie-protocol-prototype.md)。本轮不把测试作品作为交付目标，研究结论服务于 OpenNovel 自身的获取能力。

## 本轮结论

公开客户端实现提供了可追踪的调用关系，但尚无官方文档或本项目成功响应证明这些行为就是可复现的正常官方读取契约。不能把补几个通用参数当作全文协议完成，也不能从一次空响应断言必须登录或必须注册设备。

本轮没有运行外部客户端，没有复用其签名/解密算法或读取设备池，没有请求陌生正文服务；没有再次请求已触发验证的商业平台章节。仍未取得番茄网页后续章节的完整正文，App 渠道未接入产品。

## OpenNovel 本轮改动

为现有研究原型抽出私有传输函数，生产入口仍先校验模式与数字 ID，再构造固定 HTTPS 地址。没有公开自定义 URL、请求头或超时入口，没有增加桌面 IPC、来源注册、数据库迁移或队列行为。

读取响应失败时统一返回不含请求 URL/ID 的错误，避免传输异常将输入参数带进终端输出。成功报告仍只含固定元数据，不输出正文或任意服务器消息。

新增 3 项原创本机 HTTP 测试，调用原型实际使用的传输函数：

1. 302、带验证头的 200、403、429、503：检查停止分类、正文未读取，并观测服务端请求计数为 1；同时检查没有 Cookie 或账户认证头。
2. 原创 JSON 正文通过候选检查；超过上限的响应读取最多 2 MiB 加一个字节，不按正文成功处理。
3. 正文截断和延迟超过超时：返回错误，没有重试，错误中没有章节 ID 或本机地址。

测试服务仅绑定系统分配的 `127.0.0.1` 端口，使用原创文本，结束后关闭。请求计数是在响应后 200ms 的受控观测窗口内取得，不能代替所有系统或所有协议错误下永不重试的证明。未覆盖 gzip 压缩炸弹、真实官方会话、真实验证通过或原生界面。

首次并行回归出现连接失败，临时诊断取得 Windows 10053（本机中止连接），不能只按超时解释。测试服务改用写方向关闭及等待客户端结束，避免写完响应立即丢弃连接；普通用例请求预算与生产原型同为 15 秒，独立超时用例仍为 1 秒预算与 3 秒服务端延迟。修改后完整核心单元测试 24 项通过；生产请求预算、重试策略和限制语义未改变。临时原始异常诊断已移除，首次失败日志仅保留于忽略目录。
