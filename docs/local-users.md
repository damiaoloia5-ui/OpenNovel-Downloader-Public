# 本地用户与干净分发

## 使用方法

启动软件后，在左侧「当前用户」展开「切换／新建用户」。填写名称，点「新建空白用户」，再点「切换用户」。新用户书库为空，不继承其他人的书籍、平台账号记录、任务、登录会话或界面偏好。切换会重新打开程序并关闭原登录窗口；先暂停正在保存的任务，等待文件生成完成。

再次启动会记住上次选择的用户。用户名称只是显示名称，磁盘使用随机 ID 分区，重名会提示修改。当前版本不提供删除用户按钮，避免误删书籍。

在「添加小说」选择章节范围、TXT／Word 和文件夹后保存。默认路径位于当前系统用户的应用数据目录中：Windows 为 `%APPDATA%\org.opennovel.downloader\profiles\<随机ID>\exports`，每本书一个子目录。程序和用户数据分开，复制安装包不会复制书籍。自己选择公共文件夹时，其中的导出文件仍由该文件夹的系统权限决定。

原有默认书库会登记为「原有书库」，保留原位置，不复制到新用户。维护人员用 `--database <path>` 打开旧库时也登记独立数据空间；该明确参数始终指定该书库。正常桌面快捷方式不应附带个人数据库路径。`--adopt-library <绝对路径>` 只登记并选中旧库，不打开、迁移或复制其中正文。

CLI 不指定 `--database` 时使用同一系统用户上次选择的本地用户；可以用 `--profile <ID>` 明确选择。GUI 和 CLI 不能同时写入同一书库。显式 `--database` 的 CLI 默认导出放在该数据库对应的 `.data/exports`，避免不同命名数据库默认混用同一导出目录。

## 隔离边界

书库（含任务、账号记录、导出历史）、WebView 数据、临时官网会话、本地引擎启用偏好和默认导出目录按用户 ID 分开。各 Windows 账号另有独立系统数据目录。配置损坏或用户 ID 无效时停止打开，不静默回退到别人的书库。

软件内用户用于分开管理，不是密码登录、加密或访问控制。同一个 Windows 账号下的人能够切换这些用户，也能通过文件管理器读取其文件；需要互相保密时，请使用独立 Windows 账号及系统文件权限。应用不阻止管理员访问文件。

## 给其他人分发

只发送重新生成的安装包或经过检查的便携 ZIP，不要发送自己运行过的整个项目、数据目录或旧交付目录。

`npm run desktop:package` 和 `npm run desktop:package:integrated` 在打包前执行资源白名单检查；一体化组件同时校验固定清单和文件 SHA-256。发现多余的数据库、小说文件、用户列表、Cookie、缓存、隐藏配置或被替换的白名单文件时阻止打包。书库不会作为模板复制，新电脑首次启动建立空书库；如果机器原本装过本软件，则保留该机器自己的原有数据。

便携包通过 `node scripts/package-portable.mjs <新的输出目录>` 从明确清单构建：程序、许可证、操作说明及固定组件；不复制项目目录。交付前逐文件校验并生成 ZIP。自检使用原创两章样本，输出放在单独验证目录，不进入便携包。

正式签名、独立干净系统安装和真实平台权益验收仍需按各自发布门禁完成；本次隔离与分发检查不代替这些验收。
