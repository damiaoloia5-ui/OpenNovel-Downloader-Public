# 0010：显式账户会话中的自动逐章保存

日期：2026-10-25；状态：已实施，真实登录权益及 VIP 全书覆盖待验收。

## 问题

起点已经能确认完整目录、预览并保存当前正常显示的章节，但逐章操作无法满足长篇的本地保存需求。已有下载队列具备持久状态、暂停取消、缓存复用和事务完成，应该复用这些机制。

## 决策

- 保留 `qidian-session` 来源，不开放普通 HTTP 下载能力。只有核心的已保存目录入口能创建自动任务；前端不抓正文、不写数据库。
- 复用 jobs/job_items，章节 payload 加入仅由本地生成的 `automatic_session=true`，区分手动保存记录。schema 仍为 8，页面 DTO 不接受该标记或额外字段。
- 桌面端显式选择起点账户和已确认目录，默认全目录，可选原有序号范围语法。已有正文跳过；正文与完成标记同事务提交。任务范围完成与整书保存比例分别展示。
- 浏览器适配器只导航正常官方章节链接并读取正常渲染文字；全局同时最多一个自动浏览器任务，串行翻页最小间隔 3 秒，单章 30 秒截止。只轮询同一页 DOM，不自动刷新或重新请求。
- 两次间隔读取结果相同才交给核心；核对源、书号、章号、标题和声明字数。过滤隐藏、模糊、保护字形，拒绝未完整正文。
- 登录跳转、订阅提示、可见验证码框、未知结构、身份变化或超时立即停止，保留后续 queued 状态；只有显式选择账户继续才重试失败/受限章。其他公开 HTTP 来源的行为保持原状。
- generation 防止使用已关闭或重开的会话，revision 防止读取期间导航变化。读取租约阻止软件入口同时导航，取消感知等待并丢弃迟到正文；关闭账户窗口也会使任务停止。
- 使用现有临时隔离浏览器，不复制或持久化凭据。任务不永久绑定账户 ID；重启后必须本人重新选择账户、打开窗口并确认后继续，不能由后台任务自动登录。
- 开始和继续都要求用户确认官网已关闭自动订阅。软件不点击购买或订阅，但不能替用户推断官网账户的自动购买设置。

## 权衡与边界

官网窗口会逐章切换，用户操作该窗口会中止任务。休眠、失效会话和变动页面要求本人处理后继续。严格匹配可能拒绝实际有权限的内容；宁可保留缺章，也不把截断、保护文字或其他章节当成完整正文。

不新增 Cookie 接口、第三方正文服务、OCR、保护解除、验证码处理、自动购买或通用 VIP 破解。UI 的自动保存是实验能力，受控队列完成不能代替真实已购全书验收。

## 验证

原创三章适配器覆盖完整下载/导出、缓存跳过、受限停止、显式继续、暂停迟到结果、重启、范围完成、标题不匹配及事务回滚。真实 DOM 契约和原生官网有界测试另见 [验证记录](../verification/2026-10-25-automatic-session-download.md)。普通 CI 不访问商业小说平台。
