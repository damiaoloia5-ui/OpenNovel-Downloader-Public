# ADR-0001：共用核心与首轮本地导入验证

- 日期：2026-10-14
- 状态：工程基础已实施；商业来源及完整 W02 准入以验证记录为准
- 依据：PROJECT_PLAN.md 第 7、8、9、16、18 节

## 决策

采用 Rust workspace，核心与 CLI 分离，桌面通过 Tauri 命令调用同一个核心。前端 Vue/TypeScript 不承担文件导出和数据库操作。界面没有伪造成功状态。

首个可执行入口采用用户提供的本地 JSON 文档。它是独立的本地导入能力，建立持久任务、事务、取消与离线导出基础，不作为 W03 的商业来源验证。

数据库使用 bundled SQLite，WAL + FULL synchronous。短事务在核心互斥连接上串行执行；桌面把数据库和导出工作放入阻塞工作池。操作系统文件锁约束同一书库的写入实例。持久队列先保存导入正文，章节提交后释放队列正文，避免恢复依赖临时内存。

取消信号在调度前和章节提交前检查。取消后已经提交的章节仍可导出，重新执行只处理未完成项。启动恢复将执行中的任务标记为 paused。作品和章节身份使用字符串，顺序单独存储。

导出读取一个 SQLite 事务快照，完成写入和文件同步后原子发布到同目录。已有文件拒绝覆盖，部分导出带 partial 文件名和覆盖说明。EPUB 所有输入按 XML 文本转义。

## 当前约束及后续

本轮没有 HTTP 下载、平台账户、目录快照与正文修订。导入输入限制 16 MiB/10000 章，当前导出快照会载入内存。网络长篇场景需要在 W06/W07 扩展流式处理和资源预算，不能把该限制当作所有来源的永久模型。

本地任务先采用阻塞工作池，不添加无实际用途的网络运行时。网络适配实施时再引入 Tokio、请求预算、访问状态和按章节错误分类。

原生应用使用系统应用数据目录。CLI 可显式指定路径；两个入口不能同时写同一书库。系统文件锁在正常结束或进程终止后释放。

许可证仍待所有者决定，Apache-2.0 是计划候选。没有复制参考项目代码或使用其私有实现。
