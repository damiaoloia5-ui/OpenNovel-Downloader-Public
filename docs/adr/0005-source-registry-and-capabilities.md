# ADR 0005：来源注册、能力声明与持久任务路由

日期：2026-10-21。状态：已实施，0.2.0 候选版。

## 问题

只有番茄时，CLI 和桌面后台直接持有 Fanqie 客户端。增加七猫后，输入识别、来源展示、继续/重试必须正确选择来源；书旗目前只有目录，不能将可 inspect 误当成可下载。跨平台数字 ID 相同也不能命中另一作品的缓存。

## 决策

核心建立静态来源清单和 SourceHub，统一提供链接识别、显式前缀、能力描述、inspect 分发与正文适配器获取。客户端按来源惰性初始化。纯数字保留番茄旧语义，其他平台使用官网链接或显式前缀，不自动试遍全部平台。

正文仍使用现有 SourceAdapter。七猫实现该契约，书旗不实现；can_download=false 同时作用于界面与核心建任务前检查。恢复、重试和更新根据持久任务/书籍的来源 ID 路由，来源不匹配时拒绝。数据库继续以 (source, remote_id) 作为作品身份，章节 ID 保留字符串；schema 4 不变，无迁移。

从已有番茄实现抽出共享 WebClient，复用 HTTPS、来源主机名单、大小预算、超时、限流、取消和受控重定向，字体及网页解析留在各来源。七猫实测响应需要旧式折行头兼容，只在其客户端启用；默认严格解析不变，保留 TLS 和 URL 校验，以本地响应测试覆盖兼容范围。

GUI/CLI 不各自维护能力表，不在前端抓取；书旗未知阅读状态不显示“开放”。导出复用同一内容模型，所有网络正文来源的完整快照文件名带章节数，以保留旧文件。

## 取舍与验证

静态注册需要新增来源时修改 Rust 分发，但当前三个来源可读、可审计，不需要动态插件及独立权限模型。能力目前只有 can_download，后续出现真实登录/搜索需求时再扩展，避免空契约。

HTML 和接口变化会导致显式拒绝；不能将截断、错书或未知权限标为完成。长度检查是启发式，真实多样本覆盖仍需扩大。

原创测试验证 ID 隔离、错误适配器拒绝、权限和完整目录、推荐正文隔离、取消重开继续、追加章节与快照导出。真实原生测试验证七猫暂停 2/4 后重启继续为部分 3/4，并验证书旗禁用下载。详见 [验证记录](../verification/2026-10-21-multi-source.md)。
