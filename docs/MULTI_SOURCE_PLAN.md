# 多来源接入实施方案

日期：2026-10-21。起点：`ad046c7`，工作区干净。沿用用户确认的官网公开内容范围。

## 本轮交付

1. 七猫官网：详情、完整目录、明确免订阅章节的下载、选章、持久恢复、离线预览和共用 TXT/EPUB。目录的 VIP 标记不等同于 App 广告免费，受限章节不请求正文。
2. 书旗官网：详情和完整目录先接入。样本正文连续两次返回 HTTP 429，第二次 Retry-After=62 秒；本轮不继续重试风暴，不将正文标为已支持。GUI 禁用下载、CLI 明确拒绝，保留后续升级入口。
3. 提取统一来源识别与客户端注册：根据官网链接或显式来源 ID 前缀路由；恢复与重试按持久任务的来源选择适配器。纯数字输入保持番茄兼容，不猜测跨平台重名 ID。

## 当前实测与实施依据

- 七猫：官方作品 `https://www.qimao.com/shuku/222767/`；官网部署脚本公开调用 `/api/book/chapter-list?book_id=...`。本次返回 4,100 项、14 项 is_vip=0。第一章网页有主章节容器、标题及字数。受限章节页还包含其他作品的推荐正文，因此只在主章节容器读取，并校验标题和声明长度，禁止从整页全部 p 标签拼接。
- 书旗：`https://www.shuqi.com/book/9147568.html` 与 `/chapter?bid=9147568` 返回 11 章完整目录。详情含独立 JSON 元数据；不执行内嵌脚本，不使用页面临时 token 或账户。正文限流属于当前获取条件，不代表该作品永久不可读，也不代表其他作品已验证。

实时网页和正文只在忽略目录保留；测试样例独立原创，不把采集内容加入 Git。

## 架构与改动边界

- `crates/core/sources`：来源识别、能力描述、懒加载客户端、受限 HTTP 访问、七猫解析及书旗目录解析。只注册明确实现的来源；不引入远程代码插件。
- 原有 Fanqie 保持契约；复用其已验证的 HTTP 预算实现，来源主机名单相互独立，保持取消、超时、大小上限及 Retry-After。
- GUI/CLI 通过同一核心能力清单识别来源、限制下载与恢复。来源不具备正文能力时，在建任务前返回原因。
- 书籍仍以 `(source, remote_id)` 区分，章节 ID 保留字符串，目录位置独立。无需 schema 迁移，不变更已有正文与任务。
- 通用任务、事务、选章导出、离线预览继续复用；网络快照文件名按所有可下载来源使用 complete-N，避免新增来源更新后同名覆盖。

## 验证与提交

新增原创契约测试覆盖：官网链接与 ID 前缀、域名/路径拒绝、目录数量与顺序、VIP/未知权限拒绝、只读主章节容器、推荐正文污染、错章与截断、来源身份隔离、错误适配器恢复拒绝、书旗目录不误报正文支持。

运行 Rust fmt/clippy/test、前端 lint/typecheck/build；独立真实样本下载和 EPUBCheck，再进行原生来源识别、目录、选章、保存与重启恢复检查。打包保留 v0.1 安装器，另生成多来源候选包。检查差异、只提交本轮文件，不 push、不自动打 tag。
